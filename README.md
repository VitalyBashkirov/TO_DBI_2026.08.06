Адаптация АБС «ЦФТ-Банк» под архитектуру DBI

## 📌 О проекте

Этот проект посвящён адаптации локального кода АБС «ЦФТ-Банк» для перехода с платформы Oracle на платформу **2MCA DBI (PostgreSQL)** в рамках импортозамещения в "Народном банке".

**Ключевая задача:** обеспечить бесшовную работу банковской системы на новой СУБД без потери функциональности и производительности.

### Почему это важно?

Переход на отечественное ПО — стратегический тренд и требование регулятора для банков как субъектов КИИ. Архитектура DBI (Database Independent) позволяет исполнять единый прикладной код на разных СУБД, что критически важно для миграции с Oracle на PostgreSQL.

**Масштаб системы:**
- 8 тыс. таблиц
- 50 тыс. методов
- 13 тыс. представлений
- 12 млн строк кода дистрибутива + тысячи строк локального кода

## 🏗 Архитектура решения

Система строится на трёхуровневой архитектуре ЦФТ:
 
 1.Прикладной код (локальные доработки банка)
 2.Технологическое ядро (ЦФТ-Платформа) с поддержкой DBI
  3.1 Oracle ТЯ1 (исходная БД)
  3.2 DBI PostgreSQL (целевая платформа)

**Подход:** адаптация кода (не переписывание с нуля) через доработку Технологического ядра и модификацию локальных объектов.


## 🚀 Этапы проекта

Проект структурирован по этапам, основанным на успешных практиках миграции ЦФТ-Банк:
### Этап 1. Адаптация кода под DBI
| Задача                         | Инструменты/Методы 
|--------------------------------|-------------------
| Инвентаризация локального кода | Анализ на предмет использования Oracle-специфичных конструкций 
| Создание регрессионных тестов  | Пакет `DBI Regress` для покрытия затронутого функционала 
| Создание нагрузочных тестов    | Пакет `DBI perform` для проверки производительности 
| Адаптация локального кода      | Переработка PL/SQL → PL/pgSQL с учётом требований DBI 
| Валидация                      | Регрессионное + нагрузочное тестирование 

### Этап 2. Миграция данных и переход
1. Усечение исторических данных (технология **CutWYN SBS** — до 70% объёма)
2. Миграция Oracle → PostgreSQL
3. Переход на тестовую платформу 2MCA DBI
4. Переход на промышленную платформу 2MCA DBI

### Этап 3. Тестирование и валидация
- Регрессионное тестирование с использованием `DBI Regress`
- Нагрузочное тестирование с использованием `DBI perform`
- Проверка на целевых объёмах данных

## 🛠 Технологический стек

| Компонент                    | Технология 
|------------------------------|------------
| **Исходная СУБД**            | Oracle 
| **Целевая СУБД**             | PostgreSQL / Postgres Pro (включена в реестр Российского ПО)
| **Платформа**                | ЦФТ-Платформа 2MCA DBI
| **Инструменты тестирования** | DBI Regress, DBI perform
| **Инструменты миграции**     | CutWYN SBS (усечение исторических данных)
| **Языки**                    | PL/SQL → PL/pgSQL, Java (jar-приложения)
