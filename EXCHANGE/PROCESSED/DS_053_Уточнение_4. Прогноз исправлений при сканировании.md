## Контекст

В DS_053_Уточнение_3, задача A было указано:

> «если активен хотя бы один флаг — содержимое: заголовок + PLAN, **без** блоков `>` / `<КР>`»

KODA реализовала буквально: `scan_VVxVVx_*` при сканировании содержит только заголовок и `PLAN: —` (пустой). **Это не соответствует замыслу.**

**Что нужно на самом деле:** `scan_VVxVVx_*` при сканировании должен быть **прогнозом** — тем, что произошло бы, если нажать «Исправить код». То есть:

- прогнать `issues` через **тот же конвейер**, что при фиксе;
- собрать PLAN и пары «Было → Станет»;
- **не записывать** изменения в исходный файл.

**Текущий лог (неверный):**

```
Режим: сканирование (исправления не выполнялись)
**PLAN**: —
Правил в PLAN: 0
_Блоков «>» / «<КР>» нет: исправления не выполнялись._
```

**Ожидаемый лог (прогноз):**

```
Режим: сканирование (прогноз исправлений, без записи)

PLAN: v53.PROC.ID_SIZE.п.3.27, plpcheck.BAD_PREFIX, ...

Правил в PLAN: N

Прогноз:
Строка 32:
..........................> vDateRep varchar2(10);		-- отчетная дата...
<v53.PROC.ID_SIZE.п.3.27>   vDateRep varchar2(20);		-- отчетная дата...
Строка 33:
...

Статистика по файлу:
  v53.PROC.ID_SIZE.п.3.27: 2
  plpcheck.BAD_PREFIX: 1
  ...
```

## Требования

### `scan_VVxVVx_*` при «Сканировать» — прогноз

1. **Прогнать конвейер в режиме симуляции:**
   - `issues` от сканера → `sql_parser.apply_fix` (regex + hybrid) → `DeterministicFixer` → `FIXES` (backup);
   - собрать `changes_log` — как при фиксе;
   - **не записывать** изменения в исходный файл (файл не трогается).

2. **Записать `scan_VVxVVx_*`:**
   - заголовок — как сейчас (рубрикаторы, флаги, дата, источник);
   - режим — «**прогноз исправлений, без записи**» (заменить «исправления не выполнялись»);
   - **PLAN** — перечень КР-кодов, которые **сработали бы**;
   - **«Правил в PLAN»** — количество;
   - блок **«Прогноз:»** (заголовок блока) — пары `>` / `<КР>` по Схеме A;
   - **«Станет»** вместо «Стало» — в текстовых пояснениях (если есть);
   - статистика по файлу — по сработавшим правилам (как при фиксе).

3. **Формат пар `>` / `<КР>`** — как в Схеме A из DS_053_Уточнение_2 (точки МД+1, выравнивание `<КР>` до МД+2).

4. **Только прогноз** — файл на диске **не изменять**.

### Без флагов — без изменений

`scan_VVxVVx_xxxxxx_*` при сканировании без флагов — **пустой**, с пометкой «флаги не выбраны». Без PLAN и без пар `>` / `<КР>`. (Как сейчас.)

### `scan_report_*` — без изменений

`scan_report_*` при сканировании — табличный отчёт (как сейчас). Прогноз — только в `scan_VVxVVx_*`.

## Задачи KODA

### Задача A — Реализовать прогноз в `save_scan_only_log()`

В `code_fixer.py`, функция `save_scan_only_log()` (или аналог):

1. **Не просто PLAN, а симуляция:**
   - вызвать `_apply_issue_fixes()` (или его аналог) в режиме **без записи** — передать `dry_run=True` или подобный флаг;
   - получить `changes_log` — как при реальном фиксе.

2. **Записать в лог:**
   - режим: «**прогноз исправлений, без записи**»;
   - PLAN: перечень сработавших КР-кодов;
   - блок «**Прогноз:**» с парами `>` / `<КР>`;
   - статистика: по сработавшим правилам.

3. **Не записывать** изменения в исходный файл.

### Задача B — Проверить `_apply_issue_fixes()` на поддержку dry-run

В `code_fixer.py`, метод `_apply_issue_fixes()`:

- если у него **нет** режима dry-run — добавить параметр (например, `dry_run: bool = False`);
- при `dry_run=True`:
  - правила применяются к **копии** `lines[]` (in-memory);
  - `changes_log` формируется;
  - исходный файл не перезаписывается.

### Задача C — Убедиться, что файл не меняется при сканировании

**Требуется:**

- после прогона «Сканировать» с активными флагами — файл-источник **не изменён** (проверить `md5`/`sha` до и после);
- изменения — только в `scan_VVxVVx_*` (прогноз).

## Что НЕ делать

- ❌ Не записывать изменения в файл-источник при сканировании.
- ❌ Не менять `scan_report_*` — он остаётся табличным.
- ❌ Не менять `scan_VVxVVx_*` при «Исправить код» — там всё как было (PLAN + was/became).
- ❌ Не использовать каталог `logs\temp\` — все логи в `logs\`.
- ❌ Не трогать `logs\temp\DS_053\synthetic.plp` (Тест 1).
