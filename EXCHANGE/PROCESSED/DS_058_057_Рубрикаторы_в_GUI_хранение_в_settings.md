## 1. Цель

**Одна правка `gui_app.py` + `settings.json`, которая:**

1. **Убирает баг:** GUI **никогда не пишет** в `1.RUBRICATOR_FILES v5.md`. Хранение состояния — в `settings.json`.
2. **Добавляет 4 чекбокса рубрикаторов** (v53 / тдс / тклоик / PlpCheck) вместо текущего одного.
3. **Добавляет тултипы** для всех кнопок и чекбоксов.

**Результат:**
- `1.RUBRICATOR_FILES v5.md` — **read-only** для GUI;
- состояние чекбоксов хранится в `settings.json` → `rubricator_selected_rules` (словарь);
- 4 независимых чекбокса;
- тултипы везде.

## 2. Схема хранения (согласовано)

### 2.1. `settings.json` — новый ключ

```json
{
  "rubricator_selected_rules": {
    "v53.rule_code_1": true,
    "v53.rule_code_2": false,
    "тдс20240828.DML_JOIN.стр.1": true,
    "тклоик20240828.NO_GOTO.стр.5": false,
    "plpcheck.CODE_IN_COMMENT": true
  }
}
Ключ верхнего уровня: rubricator_selected_rules.

Формат: словарь {"<rule_code>": true|false}.

Идемпотентен — повторная запись не теряет состояние выключенных.

<rule_code> — из 4.RUBRICATOR_PROMPT v5.json (для v53 / тдс / тклоик) и из rule-description.html (для PlpCheck).

2.2. Начальное состояние (при первом запуске / отсутствии ключа)
Вариант C — согласован:

Если ключа rubricator_selected_rules нет в settings.json:

прочитать 1.RUBRICATOR_FILES v5.md (через _load_rubricator_files);

+ → true, − и всё остальное → false;

сразу сохранить результат в settings.json → rubricator_selected_rules.

Если ключ есть — использовать только его, файл рубрикатора не читать для состояния чекбоксов.

2.3. Появление новых правил
Согласовано: при каждом запуске — дополнять settings.json новыми правилами (сохраняя уже выбранные):

для каждого правила из рубрикатора, которого нет в rubricator_selected_rules — добавить со значением false (выключено по умолчанию);

уже существующие записи не трогать.

3. Что сделать
Шаг 1. Разделение чтения рубрикатора и состояния GUI
_load_rubricator_files (765–791) — оставить как функцию чтения рубрикатора (для сканирования и первичной инициализации). Не использовать для начального состояния чекбоксов, если ключ rubricator_selected_rules уже есть.

_populate_rules_tree — начальное состояние чекбоксов брать из settings.json → rubricator_selected_rules (а не из _load_rubricator_files напрямую).

Логика первого запуска (вариант C): при отсутствии ключа — прочитать 1.RUBRICATOR_FILES v5.md, сформировать словарь, сохранить в settings.json.

Логика дополнения: при наличии ключа — дочитать рубрикатор (только для получения списка всех rule_code), добавить отсутствующие как false, сохранить (если были добавления).

Шаг 2. Убрать запись в рубрикатор
_save_rubricator_state (1889–1945) — удалить или переписать так, чтобы она писала в settings.json → rubricator_selected_rules, а не в 1.RUBRICATOR_FILES v5.md.

При сохранении состояния — брать актуальное состояние чекбоксов из GUI (или из rules_changed).

Обновлять словарь в settings.json.

Не трогать 1.RUBRICATOR_FILES v5.md.

save_settings() (1887) — вызывает _save_rubricator_state → теперь пишет в settings.json.

Шаг 3. Четыре чекбокса рубрикаторов
В _populate_rules_tree — добавить 4 чекбокса верхнего уровня:

v53 — правила с префиксом v53. в rule_code;

тдс — префикс тдс20240828.;

тклоик — префикс тклоик20240828.;

PlpCheck — префикс plpcheck. (из rule-description.html).

Переключение родительского чекбокса рубрикатора — включает/выключает все правила этого рубрикатора (устанавливает true/false для всех его rule_code).

Переключение дочернего (конкретного правила) — обновляет только его.

Состояние всех чекбоксов синхронизировано с settings.json → rubricator_selected_rules.
