### Ключевой инцидент чата 22: BOM и .ps1

**Симптом:** close_ds.ps1 запускался через PS 5.1 → 5 ложных ошибок
парсинга на L79, L85, L201, L204 («Непредвиденная лексема }»).
В сообщении кириллица отображалась как кракозябры.

**Ошибочные гипотезы (отвергнуты):**
1. LF вместо CRLF → нормализация в CRLF не помогла.
2. [Parser]::ParseFile ненадёжен → ParseInput давал 0 ошибок.
3. Битый текст → hex чист, баланс скобок OK.

**Настоящая причина:** PowerShell 5.1 при запуске .ps1 БЕЗ BOM читает
файл в системной ANSI-кодировке (CP1251 на русской Windows).
UTF-8 байты кириллицы интерпретируются как CP1251 → кракозябры →
парсер видит искажённые строки → ложные ошибки.

**Решение:** запись close_ds.ps1 С BOM (EF BB BF). После этого:
- L204 через Get-Content default → корректно.
- AST ParseFile → 0 ошибок (1083 токена).
- Боевой запуск → работает.

**Зафиксировано:** Урок I (п.6 §6.2.1 + §6.1).

## Уроки чата 22 (в DS_STANDARD.md §6.2.1)

### Урок G: -Filter в Get-ChildItem не поддерживает regex-классы

- ПЛОХО: Get-ChildItem -Filter 'DS_12[1-5]*' → не работает.
- ХОРОШО (wildcard): Get-ChildItem -Filter 'DS_12*'.
- ХОРОШО (Where-Object): Get-ChildItem | Where-Object { $_.Name -match '^DS_12[1-5]' }.

### Урок H: [Parser]::ParseFile и BOM

- При ОТСУТСТВИИ BOM у .ps1 с кириллицей:
  - [Parser]::ParseFile читает файл в ANSI (CP1251) → ложные ошибки.
  - [Parser]::ParseInput с ReadAllText(UTF8) → 0 ошибок.
- Корень проблемы — не метод, а отсутствие BOM.
- ХОРОШО: обеспечить BOM у .ps1 (см. Урок I).

### Урок I: .ps1 с кириллицей требует BOM в PS 5.1

- PS 5.1 при запуске .ps1 БЕЗ BOM читает файл в системной ANSI
  (CP1251 на русской Windows). Кириллица → кракозябры → ложные
  ошибки парсинга.
- ХОРОШО: записывать .ps1 с кириллицей С BOM:
  $utf8WithBom = New-Object System.Text.UTF8Encoding($true)
  [System.IO.File]::WriteAllText($path, $text, $utf8WithBom)
- ПРОВЕРКА: $bytes = [IO.File]::ReadAllBytes($path)
  BOM = ($bytes[0] -eq 0xEF -and $bytes[1] -eq 0xBB -and $bytes[2] -eq 0xBF)

### Урок C (повторён в DS_126): абсолютные пути для .NET методов

- ПЛОХО: [System.IO.File]::WriteAllText('tools\file.py', ...) →
  DirectoryNotFoundException (ищет относительно стартовой директории
  процесса, а не $PWD).
- ХОРОШО: [System.IO.File]::WriteAllText('F:\TO_DBI\tools\file.py', ...).
- Или: $p = (Resolve-Path -LiteralPath 'tools\file.py').Path.
