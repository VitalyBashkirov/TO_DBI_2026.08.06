# Промпт: создать рубрикатор в виде трёх текстовых файлов-таблиц

## Задача
На основе предоставленных документов создать три файла в формате Markdown:

1. `1.RUBRICATOR_FILES.md` — перечень файлов с инструкциями, рекомендациями, регламентами, требованиями.
2. `2.RUBRICATOR_CATEGORIES.md` — группировка исправлений по категориям.
3. `3.RUBRICATOR_FIXES.md` — полный перечень требуемых исправлений.

## Требования к оформлению таблиц
- Использовать выравнивание: левое (`:---`) для всех колонок.
- Для читабельности ЖЕСТКО соблюдать ширину колонок (символов):
  - N: 3
  - Признак: 8  (`+`действующий, `-`нет)
  - Код файла: 16
  - Полное имя файла: 124
  - Код категории: 14
  - Описание категории: 120
  - Коды Файла.Категории.Исправления.Пункт/Стр : 42
  - Пункт(ы) (документации): 10 (если пункт не определен, то заполнить пробелами. Для случаев `п.22, 23` заполняем как `п.22,23`)
  - Строки (документации): 10 (если вычислен Пункт(ы) не заполняем)
  - Короткое описание: 50
  - Подробное описание: 80–1024
  - Последний символ в строках таблиц `|` не нужен
  - В строке разметки типа `|:----|:-------------|:`
    не испольховать символ `:`
  При формировании поля заголовка, если длина меньше допустимой, дополни ее пробелами
  Если больше допустимой, остаток переносить на вторую строку заголовка с соблюдением разметки для предыдущих колонок.
  Если при формировании строки значение поля располагай с первого символа (пробел не нужен). Если длина поля для колонки недостаточна, поле дополнить пробелами.
  Если превышает ширину колонки в этой строке можно превысить до требуемой, но тогда ширину следующей колонки уменьшить. Ширину последней колонки не ограничивать.

## Файл 1: `1.RUBRICATOR_FILES.md`
### Структура таблицы
| N | Признак | Код файла | Полное имя файла |

## Файл 2: `2.RUBRICATOR_CATEGORIES.md`
### Структура таблицы
| N | Код категории | Описание категории |

## Файл 3: `3.RUBRICATOR_FIXES.md`
### Структура таблицы
| N | КодыФайла.Категории.Исправления.Пункты/Строки | Пункт(ы) | Строки   | Короткое описание                               | Подробное описание

### Правила формирования кода исправления
Формат: `Код_файла.Код_категории.Код_исправления.Диапазон_строк`
- `Код_файла`: v50, тдс20240828, тклоик20240828
- `Код_категории`: SQL, STOR, PROC, INT, CACHE, DEV, LOCAL
- `Код_исправления`: краткое название латиницей (OUTERJOIN, ROWNUM, DECODE и т.п.)
- `Пункт(ы)`: п.22,23 (строго соответствует "Пунктам документации")
- `Диапазон_строк`: стр.12 или стр.12-13 (строго соответствует колонке «Строки документации» (для v50 или где пункты не определены однозначно, не заполняем)

**Примеры:**
- `v50.SQL.OUTERJOIN.п.1.1`
- `v50.SQL.ROWNUM.п.1.2`
- `тдс20240828.SQL.ANSI_JOIN_ANNOTATION.стр.3-4`

### Содержание для каждого документа
Выровнять по разметке ниже
| N | КодыФайла.Категории.Исправления.Пункт/Стр| Пункт(ы)| Строки| Короткое описание                                   | Подробное описание
**Специальные правила замены:**
- `"FTC_"` заменить на `"PSH_"`
- `"ЦФТ"` заменить на `"Банка"`
- `"префикс банка"` заменить на "префикс банка `[ПСБ]`"

Файл 3: `3.RUBRICATOR_FIXES.md` не нужно разбивать на несколько частей по документам. Все должно идти одним потоком.

## Требования к выводу
1. Выдать три файла целиком в формате Markdown
2. Кодировка: UTF-8
3. Разделители в таблицах: `|`
4. Нумерация строк в таблицах сквозная в пределах каждого файла
5. Колонки должны быть выровнены для читабельности (см. ширину выше. Если ширины колонки в стороке не хватает, ее можно увеличить)
6. Последний символ в строках таблиц `|` не нужен.

Если какие-то файлы не предоставлены, сообщи.
