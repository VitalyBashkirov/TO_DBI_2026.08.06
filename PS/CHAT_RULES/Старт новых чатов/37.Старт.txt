### §6.6.27 — CRLF-safe правки .py: splitlines, не replace

**Правило:** для правок `.py` **НЕ использовать** `str.replace(anchor + "\n", "")`.

**Инцидент чата 36 (N3a):** в CRLF-файле после `anchor` идёт `\r\n`, а не `\n`.
`replace` «находит» частично, **удаляет `\n`, оставляя `\r`** — `\r` прилипает
к следующей строке, **удваивает отступ** → `IndentationError`.

**Правильно:**

```python
lines = src.splitlines(keepends=True)   # сохраняет \r\n или \n
lines.pop(idx)                          # или del lines[a:b]
new_src = "".join(lines)
p.write_text(new_src, encoding="utf-8")
```

**Обязательно после записи:** перечитать файл, `ast.parse(src2)`.

**Не полагаться** на `ast.parse` до записи — файл на диске уже другой.

### Урок чата 36: `close_ds.ps1` — не дублировать DsNumber в BotLogMessage

**Правило:** в `-BotLogMessage` **не начинать** с `<DsNumber>: ...`.
Скрипт сам добавляет `[$stamp] $DsNumber: $BotLogMessage`.

**Инцидент чата 36:** `[14.10.2026 13:27:59] DS_146: DS_146 closed: ...` —
дублирование `DS_146`. Косметика, не критично.

### Урок чата 36: `DeepScanner.run()` возвращает `(stats, report_path)`

Не `dict`, а **кортеж из двух элементов**:
- `stats` — dict (`by_type`, `files_scanned`, `skipped_temporary`, `total_issues`);
- `report_path` — `Path` к записанному отчёту.

Учтено в тестах DS_146.

### git diff / git diff --stat — только через | Out-Host

Правило §6.6.1: `git diff ... | Out-Host` гарантирует попадание в Start-Transcript.

## Вывод в PS и логи — правила чатов 34/35/36

### Принципы

1. Строки «Лог: <путь>» — зелёным.
2. Ошибки — красным (`FAILED`, `[FATAL]`).
3. Заголовки секций `=== ... ===` — Cyan.
4. Итоговый статус (OK) — зелёным.
5. Данные (таблицы, git diff) — через `| Out-Host`.
6. Кириллица в Python-print через cp866 — кракозябры (§6.6.21), данные в файле корректны.
7. Python inline с `$` в строке — here-string `@'...'@` → `.py` → `python file.py`.
8. `Stop-Transcript | Out-Null` в конце КАЖДОГО блока.

### Типовой шаблон блока

~~~powershell
# ============================================================
# N1. <Название блока>
# Дата: YYYY-MM-DD
# Назначение: <что делаем>
# Ожидание: <что должно быть>
# Риски: <что может пойти не так>
# ============================================================

$ErrorActionPreference = 'Continue'
$proj = 'F:\TO_DBI'
Set-Location $proj

# N7 v7: очистка PS\ (сохраняя persist\)
if (Test-Path "$proj\PS") {
    Get-ChildItem "$proj\PS" -Exclude 'persist' -ErrorAction SilentlyContinue |
        Remove-Item -Recurse -Force -ErrorAction SilentlyContinue
} else {
    New-Item -ItemType Directory -Path "$proj\PS" | Out-Null
}
if (-not (Test-Path "$proj\PS\persist")) {
    New-Item -ItemType Directory -Path "$proj\PS\persist" | Out-Null
}

$log = "$proj\PS\<имя_блока>.log"
Start-Transcript -Path $log -Force | Out-Null
$env:PYTHONIOENCODING = 'utf-8'
chcp 65001 | Out-Null
$utf8NoBom = New-Object System.Text.UTF8Encoding($false)

# ... работа ...

Write-Host "`nOK" -ForegroundColor Green
Write-Host "Лог: $log" -ForegroundColor Green

Stop-Transcript | Out-Null
~~~

### Что НЕ делать

- Не использовать `return` в ручных блоках (правило №19).
- Не полагаться на `$LASTEXITCODE` после `Select-String` (правило №22).
- Не читать `.log` через `Get-Content` в PS 5.1 (§6.6.15) — только Python с `utf-8`.
- Не использовать `-like` для подстроки (§6.6.9) — `.Contains()`.
- Не использовать `Add-Content -Encoding UTF8` в PS 5.1 (§6.6.20).
- Не использовать `Out-File -Encoding UTF8` для `.py` — даёт BOM.
- Не использовать `str.replace(anchor + "\n", "")` для `.py` (§6.6.27).

### Кодировки

- `.py` / `.md` / `.json` / `.ini` / `.sql` — UTF-8 БЕЗ BOM (§6.1).
- `.ps1` с кириллицей — UTF-8 С BOM.
- Все файлы через `[System.IO.File]::WriteAllText` или `AppendAllText`
  с `UTF8Encoding($false)`.
