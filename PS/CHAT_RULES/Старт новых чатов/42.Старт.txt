## НОВЫЕ ПРАВИЛА / УРОКИ ЧАТА 41

### §6.6.34 — PS-строки с Python-кодом (критично, продолжение)

1-15 (из чата 40) — без изменений.
6h: close_ds.ps1 коммитит только отслеживаемые файлы. Новые .py/.md — git add ДО close_ds.ps1. Если забыли — git add + git commit --amend --no-edit + git push --force-with-lease.
6i: Tee-Object -Encoding нет в PS 5.1. Для UTF-8 лога — Out-File -Encoding UTF8 или [IO.File]::WriteAllText.
6j: в f-string Python 3.11 нельзя бэкслеш-кавычка (ни двойная, ни одинарная) внутри выражений — выносить в переменные.
6k: правки Python-файлов из PS — через chr(34)/chr(92) или [IO.File]::WriteAllText, не через here-string с бэкслеш-кавычкой.
6l: [IO.File]::WriteAllText(..., [Text.Encoding]::UTF8) -> BOM. Для BOM=False — New-Object System.Text.UTF8Encoding($false).
6m: ast.parse не принимает BOM.
6n: НЕ комбинировать Start-Transcript с Start-Process -RedirectStandardOutput в одном блоке. Для pytest — без Transcript.
6o: если Stop-Transcript падает — сессия непригодна, открыть новую.
6p: в PS 5.1 для pytest НЕ Start-Process + WaitForExit (дедлок), НЕ cmd /c "python -m pytest ... > out 2> err" (тоже висло). Работает: Start-Process -NoNewWindow -PassThru в чистой сессии, без Transcript.
6q: Python-код никогда не вставлять в PS-сессию как есть. Только через отдельный .py или python -c (не для многострочного).
6r: при сборке Python-кода из PS не комбинировать PS-строку с chr(39) внутри как значение — легко получить четыре кавычки подряд. Использовать chr(39)+chr(39) без обрамляющих кавычек.
6s: при сборке Python-кода из PS не разрывать выражение без скобок. Либо в одну строку, либо old1 = ("..." + NL + "...").
6t: блок «коммит + push» оборачивать в Start-Transcript -Path F:\TO_DBI\PS\chat41_NN_commit.log (без Start-Process). В лог — git status/add/diff/close_ds/git show/branch/log.
