## НОВЫЕ ПРАВИЛА / УРОКИ ЧАТА 42 (раздел 6.6.34, копилка)

### 6u - ROOT для диагностических скриптов в SRC/tests/
Диагностический/тестовый скрипт в SRC/tests/ - ROOT = Path(__file__).resolve().parents[2], а не parents[1].
Симптом ошибки: FileNotFoundError: ...\\SRC\\SRC\\analyzer\\scanner.py (двойной SRC).

### 6v - regex для конкретного словаря
При правке конкретного словаря в большом .py - regex должен быть привязан к имени словаря и его границам { } на нулевом отступе.
Иначе regex матчит первое вхождение кода в файле - а он может быть в PLPCHECK_RULE_NAMES, PLPCHECK_RULE_TYPES и т.п.
Пример: re.search(r"PLPCHECK_RULE_TO_CATEGORY\\s*:\\s*Dict\\[str,\\s*str\\]\\s*=\\s*\\{", src) + поиск закрывающей } на нулевом отступе -> править только блок.

### 6w - dry-run перед записью файла
Перед записью файла - вывести diff-предпросмотр (old -> new) и применять только с флагом --apply.
Иначе откат стоит git checkout + повторного прогона.

### 6x / 6y - python -c и git внутри Start-Transcript
python -c и git внутри Start-Transcript в PS 5.1 могут терять stdout.
Симптом: Write-Host до/после python виден, а вывод python - нет.
Решение: критичные проверки (AST, git status, git diff) - отдельным блоком без Transcript, прикладывать консольный вывод.
Для pytest - Start-Process -NoNewWindow -PassThru (без Transcript) или -RedirectStandardOutput в файл.

### 6z - кириллица в PS 5.1 (уточненный)
Кириллица портится только в here-string с кавычками (PS 5.1 интерпретирует байты как CP866/CP1251).
В массиве отдельных PS-строк кириллица не портится, если файл пишется через [IO.File]::WriteAllLines($path, $lines, (New-Object System.Text.UTF8Encoding($false))).
Правило: для русского текста - массив PS-строк + WriteAllLines, не here-string.

### 6aa - нельзя вставлять присваивания/if/for внутрь аргументов вызова
При правке аргументов вызова функции (например, TestGeneratorV2(...)) нельзя вставлять присваивания/if/for внутрь скобок - это SyntaxError: invalid syntax.
Выносить блок перед вызовом, а внутри оставлять только финальное значение (categories=_cats,).
Проверка: ast.parse после правки.

### 6ab - обновлять ВСЕ тесты-слепки
При фиксе дефекта, зафиксированного тестом-слепком (например, test_ds144d_a_e2_defect_snapshot), обязательно обновить все тесты, которые этот дефект фиксируют.
В нашем случае - два: test_ds144d_a_e2_defect_snapshot (DS_144d-a) и test_ds147d_gui_passes_categories (DS_147d).
Правило: перед фиксом - git grep <старый_паттерн> SRC/tests/ и обновить все совпадения.

### 6ac - если PS-блок упал на парсере
Если PS-блок упал на парсере - он не выполнился частично; но если WriteAllLines до ошибки прошел, скрипты _fix_*.py созданы и могли быть запущены в другой сессии.
Всегда проверять Get-Item tools\\_fix_*.py + git status + Select-String "^def test_" до повторного запуска.
Иначе - двойное применение фикса (первый раз - успешно, второй - падает на assert not found).

### 6ad - правка строк по индексам, а не replace
При правке многострочного блока по тексту replace может вставить блок не туда (из-за неоднозначного OLD).
Правило: для правки аргументов вызова - использовать ReadAllLines -> заменить строку по индексу -> вставить блок перед вызовом (по индексу) -> WriteAllLines.
Пример: gen_idx = find("gen = TestGeneratorV2("), cats_idx = find("categories=list(...)") -> lines[cats_idx] = prefix + "categories=_cats," -> new_lines = lines[:gen_idx] + block + lines[gen_idx:].

### 6ae - несколько тестов на один фикс
Если фикс меняет поведение, зафиксированное несколькими тестами (в т.ч. в разных файлах), - обновлять все (6ab).
Проверка: git grep <измененный_код> SRC/tests/ перед фиксом.

### 6af - git add до close_ds.ps1
Новые файлы (.py, .md) - git add ДО close_ds.ps1, потому что close_ds.ps1 коммитит только отслеживаемые файлы.
Если забыли - git add + git commit --amend --no-edit + git push --force-with-lease (п.6h, уже было, подтверждено).

### 6ag - подсветка путей логов
Всегда подсвечивать зеленым (-ForegroundColor Green) строки с путями логов:
stdout: <path>, stderr: <path>, лог: <path>, выходной файл <path>, written: <path>, summary: <path>.
Служебные заголовки секций (=== ... ===) - голубым (Cyan).

### 6ah - PS 5.1: quotes in text (new, from chat 42, EN)
In PS 5.1 do NOT use backslash + single-quote inside a single-quoted PS string in an array - it is a SyntaxError, not an escape.
Escape for a single quote inside a single-quoted PS string is only two single quotes (double single quote).
Also do NOT put the text at-sign + single-quote (here-string start) or single-quote + at-sign (here-string end) inside a PS string - the PS parser gets confused.
Rule: for text in a PS-string array use either no quotes, or two single quotes; never backslash + single-quote, never at-sign + single-quote / single-quote + at-sign inside a string.
