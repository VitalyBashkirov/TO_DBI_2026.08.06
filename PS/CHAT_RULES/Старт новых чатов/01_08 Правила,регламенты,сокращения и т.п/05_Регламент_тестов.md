# Регламент тестов (pytest)

## Точечный прогон
```powershell
& $python -m pytest <target> -q -W error::pytest.PytestReturnNotNoneWarning 2>&1 | Out-File -FilePath $out -Encoding utf8
```
`-W error::pytest.PytestReturnNotNoneWarning` — прямой запрет `return` из тестов. Если хоть один тест возвращает значение — pytest падает.

## Полный регресс
```powershell
& $python -m pytest (Join-Path $repo 'tests') -q 2>&1 | Out-File -FilePath $out -Append -Encoding utf8
```

## EAP=Continue
Перед pytest-блоком — `$ErrorActionPreference = 'Continue'`, после — вернуть `'Stop'`.
Иначе `[FATAL]`/`invalid command name` в stderr от python.exe валит PS-скрипт, хотя pytest прошёл.

## Верить $LASTEXITCODE
Только `$LASTEXITCODE` от python.exe — настоящий код pytest. `0` = все passed.

## Счёт
- Точечный: `N passed` (например `6 passed` для `test_ds183_k4_model_setting.py`).
- Полный: `378 passed` (на 2026-10-25, после `t6`).

## Шум в stderr (не ошибки)
- `[FATAL] Нет v5.json ...` — от `test_ds147a_exit_1_on_missing_0`.
- `invalid command name ..._update_buttons_state` — Tk `.after`-callback после `root.destroy()` (долг DS_184).

## Изоляция Tk
В тестах, где поднимается `tk.Tk()` и `DBIMigrationApp` — `root.destroy()` в `try/except Exception: pass`, перед destroy — `root.update_idletasks()`. См. `test_ds183_k4_model_setting.py` (t3, t4).
## 61_3. Счётчики D/M/?? (чат 61)
Считать через явные StartsWith / regex:
- `@($p | Where-Object { $_.StartsWith(' D ') })` — удалённые (unstaged).
- `@($p | Where-Object { $_ -match '^M ' })` — staged modified.
- `@($p | Where-Object { $_ -match '^ M ' })` — unstaged modified.
- `@($p | Where-Object { $_ -match '^\?\? ' })` — untracked.
Не через общий `Count` массива — путаница "54 vs 53" (чат 61, шаг 61_01/61_02).
