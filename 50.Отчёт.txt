## 1. DS_180 — МПК-маркировка det-правок (закрыт)

Коммит: 593914e.

Причина: code_fixer.py ставил якоря только при issue_changes; det-правки
(DeterministicFixer: переименования/удаления) не формировали issue_changes,
поэтому в матрице К1->К2 case 100/101 давали anchors=0 при fix_count>0.

Сделано:
- SRC/fixer/variable_parser.py:
  * _rename_variable возвращает (code, count, lines_hit), lines_hit — 1-based
    номера строк, где были замены;
  * changes переименований содержат 'lines': lines_hit; удаления — 'lines':
    [d['line'] for d in deleted]. Аддитивно, старые ключи сохранены.
- SRC/fixer/code_fixer.py:
  * _det_changes_to_unified: det_changes -> единый формат issue-правок
    (переименования по 'lines', удаления по deleted[].line; rule_code
    PlpCheck.STYLE.PREFIX_TYPE.п.4.4 и PlpCheck.STYLE.NOT_MENTIONED.п.4.8);
  * _predict_det_changes: прогноз det на временной копии (utf-8 без BOM),
    оригинал не трогается; используется при apply_fixes=False (НеАФ=on);
  * _insert_anchors: вынос anchor pipeline; якоря по issue + det; ветка
    «line_number is None» не нужна — у det теперь есть строки;
  * fix_file переписан: issue -> det (реальные/прогноз) -> единый
    anchor pipeline -> финальная запись. При apply_fixes=False ставятся
    только якоря, код не меняется.
- Тест: SRC/tests/test_ds180_mpk_det_anchors.py (6 passed).

Матрица case 100/101 на 3 .plp (PS\50_11_ds180_matrix.log):
  case 100: anchors total = 17 (files with anchors: 3/3), fix=3/2/5
  case 101: anchors total = 17 (files with anchors: 3/3), код не изменён
            (только якорные строки; подтверждено diff в PS\50_12).
