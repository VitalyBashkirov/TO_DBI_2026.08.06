## ПРАВИЛА ВЫВОДА (уточнения чатов 50-52)

- В конце КАЖДОГО PS-блока: полный путь лога зелёным:
  Write-Host ("=== Полный путь лога: {0} ===" -f $log) -ForegroundColor Green
- Кириллица в литералах — через [System.IO.File]::WriteAllText с
  New-Object System.Text.UTF8Encoding($true). НЕ Set-Content.
- Для python-скриптов из PS выставлять:
  $env:PYTHONIOENCODING = "utf-8"; $env:PYTHONUTF8 = "1"
- При патче файлов учитывать CRLF: читать/писать io.open(..., newline=""),
  нормализовать \r\n -> \n, писать обратно в исходном формате.
- Commit msg писать через UTF8Encoding($false) (без BOM — артефакт DS_180).
- При `$out = & python ... 2>&1` stdout python буферизуется; для прогресса
  использовать `& python -u script.py *> out.txt` и читать out.txt.
- При импорте analyzer/* добавлять в sys.path именно SRC (analyzer — корневой
  пакет внутри SRC, scanner.py использует абсолютный `from analyzer...`).
- `PLPlusScanner.scan_file` требует config['paths']['source_dir'] (иначе
  KeyError: 'paths').
- `RubricatorPrompts(<Path>)` — принимает Path, не str.
- `selected_rules=[]` -> загружаются ВСЕ 332 правила; `selected_rules=['plpcheck.']`
  -> ОТКЛЮЧАЕТ DS_033-многострочные проверки. Для К3/К4 на DS_033 брать
  selected_rules=[] + постфильтр по issue_type (как PS\50_49).
- Ollama: 7b не тянет prompt >6 КБ; 3b — ~20-30 с/проблема. Перед К4:
  keep_alive=0, keep_alive="0s" в запросе, format=json, num_predict=128,
  timeout=60, батч по 1 проблеме.
- При работе с корзиной: `$R...` — реальные байты файла, `$I...` — метаданные.
  `InvokeVerb("Восстановить")` на локализованной Windows может не срабатывать;
  fallback — `[System.IO.File]::ReadAllBytes($src)` + `WriteAllBytes($dst)`.
- `Test-Path -LiteralPath` для путей с `$` (корзина), иначе PowerShell
  раскрывает `$RECYCLE` как переменную.
