## 1. Цель

Закрыть **замечание** из отчёта DS_059_Уточнение_F:

> `bad_prefix_*` имеет **тот же риск** multi-line rename — рекомендована **отдельная задача**.

**Суть:** `bad_prefix_*` (`regex`) переименовывает **только объявление**. Ссылки в теле — **остаются** старыми → **несогласованный** код.

**Приоритет — минимум риска**: лучше **не фиксить**, чем фиксить неверно.

## 3. Шаги

### 3.1. Решение (вариант A — безопасный)

**Аналогично DS_059_Уточнение_F** (`PREFIX_TYPE_IN_VAR_NAME`):

- в `PARSER_SQL` — 4 правила `bad_prefix_*` → `transform_type: "ignore"`;
- **удалить** `transform` (или оставить комментарием);
- правила **остаются** в PLAN `scan_report_*` («Переименовать в …»);
- **автофикс не выполняется** — пользователь **сам** переименует **везде**.

### 3.2. Проверить `missing_prefix_*`

**Проверить:** есть ли у `missing_prefix_*` **тот же риск**?

- если **да** — **включить** их в задачу (тот же вариант);
- если **нет** — **зафиксировать** в отчёте.

### 3.3. Тесты

| # | Тест | Ожидаемый результат |
|---|------|---------------------|
| 1 | `bad_var varchar2(100);` + `bad_var := 1;` | Автофикс **не срабатывает** (A) |
| 2 | `tmp_Cnt number;` + `tmp_Cnt := 1;` | Автофикс **не срабатывает** |
| 3 | `Dp varchar2(10);` | `missing_prefix_varchar2` **не в ignore** → **фиксится** (`v_Dp`) |
| 4 | Регресс DS_059_Уточнение_E, F, D, u | PASSED |

**Ключевое:** `missing_prefix_*` **должны** продолжать работать (это **не** multi-line rename).
