## 3. Детали реализации

### 3.1. Счётчики в `scan_report_*` (§1)

**Было:**
Всего проблем: N
Всего файлов: M

text

**Стало:**
Всего проблем: N
Прогноз исправлений: X
Исправлено: Y
В AI: Z
Всего файлов: M

text

**Семантика — по режиму:**

| Режим | `Прогноз исправлений` | `Исправлено` | `В AI` |
|-------|----------------------|--------------|--------|
| **«Сканировать»** (dry-run) | X (все, что автофиксились бы) | 0 | Z (`needs_ai_fix`) |
| **«Исправить код»** (запись) | — (не выводится?) | Y (реально применено) | Z |

**Уточнение:** для «Сканировать» — **три** строки (`Прогноз`, `Исправлено: 0`, `В AI`)? Или **две** (`Прогноз`, `В AI`)?

**Рекомендация:** **три** строки всегда, для «Сканировать» `Исправлено: 0`. Единообразие.

**Как считать:**

| Счётчик | Источник |
|---------|----------|
| `Прогноз исправлений` | Число issues в bucket `regex`/`hybrid`/`backup`, для которых dry-run даёт изменения |
| `Исправлено` | Число issues, реально применённых (`_apply_issue_fixes`, только при записи) |
| `В AI` | Число issues с `needs_ai_fix = True` (DS_054/DS_068) |

**Реализация:** счётчики формируются в `generate_report` (scanner.py) и `save_scan_only_log` (code_fixer.py). Источники данных:

- `scanner.issues` — все issues;
- `fixer.results` — применённые;
- `needs_ai_fix` — из `_verify_file`.

### 3.2. Топ-файлы (§2)

**Условие вывода:**
- «Уровень логирования» = **«Подробный»** (из GUI);
- **файлов ≥ `report_stats_min_files`** (по умолчанию 10).

**Вывод — для `scan_report_*`:**
Файл с наибольшим количеством проблем:
<путь><имя.расширение> — N проблем

Статистика по файлу:
<issue_type-1>: N
<issue_type-2>: M
...

Файл с наибольшим количеством разнообразных проблем:
<путь><имя.расширение> — M видов, N проблем

Статистика по файлу:
<issue_type-1>: N
...

text

**Ключевое:**
- **`«разнообразные проблемы»` = `issue_type`** (`plpcheck.SIZELESS`, `plpcheck.UDF`) — **полное имя** из PARSER_SQL.
- **Статистика по файлу** — **та же структура**, что в `scan_VVVVVV_*` (§8.2 DS_CONTEXT): `<issue_type>: N`.

**Если один файл — лидер по обоим** — выводится **один блок** (по разнообразию).

**Вывод — для `scan_VVVVVV_*`:**

Аналогично — топ-файлы в конце статистики (после текущего блока «Статистика по файлу»).
