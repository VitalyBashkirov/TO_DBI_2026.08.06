## 3. Шаги прогона

### 3.1. Фиксация исходного состояния

- Зафиксировать: путь, размер, число строк/файлов в `patch_PSH_DEP_PRIV_GO`.
- Проверить доступность Ollama (см. §2).
- Зафиксировать `git status` (список незакоммиченных изменений DS_089b).

### 3.2. Полный прогон цикла (замер тайминга, задача A)

Последовательно выполнить (с фиксацией времени начала/конца каждого этапа):

1. **Скан** — детерминированный сканер + rule-based fixer:
python tools\rule_based_fixer.py --in-dir EXCHANGE\AI_IN --out-dir EXCHANGE\AI_OUT

text
*Примечание*: если вход для rule-based берётся из `AI_IN`, а `AI_IN`
наполняется сканером — сначала выполнить скан (команду сканера уточнить
в `DS_FILES.md` / `AGENTS.md`; если скан запускается через GUI — здесь
допустимо использовать GUI только для «1. Сканировать», но AI-цикл — CLI).

> **СТОП-развилка**: если команда сканера в CLI неочевидна и требует
> GUI — сообщить в отчёт, зафиксировать как расхождение, продолжить
> с шага 3.3 на том, что есть.

2. **AI-цикл** (batch 10 + fallback):
python tools\ai_local_worker.py --request <file> --out EXCHANGE\AI_OUT --batch-size 10

text
Зафиксировать: время начала, время конца, число fix, число skipped,
число needs_manual, число invalid_json (fallback сработал?).

3. **Merge** (если применимо) — `merge_fixes_by_line` (DS_084).
Зафиксировать результат: сколько skipped слито.

4. **Применение фиксов** — команда применения (уточнить по `AGENTS.md` /
`DS_FILES.md`). Зафиксировать applied / needs_manual.

### 3.3. Проверка resume скана (задача C)

1. Запустить скан на `patch_PSH_DEP_PRIV_GO`.
2. **Прервать** скан на середине (Ctrl+C / graceful stop — способ уточнить
по `AGENTS.md`; зафиксировать, как именно прерывали).
3. Зафиксировать: сохранилось ли состояние (`_abort_state` — только в GUI;
в CLI-режиме resume реализован на уровне файлов/ключей — уточнить
в `scanner.py` / `code_fixer.py`, какие артефакты остаются).
4. Запустить скан **повторно**.
5. Проверить: нет дублей issues, ранее обработанные отфильтрованы.

> **СТОП-развилка**: если resume в CLI-режиме **не реализован** (DS_089b
> делал resume в `gui_app.py`, а не в `scanner.py`/`code_fixer.py` —
> см. `DS_089b_report.md` §5.3–5.4) — зафиксировать это как **расхождение**,
> не имитировать. Resume-часть (задача C) тогда помечается как
> «в CLI недоступно, требуется GUI-прогон».

### 3.4. Проверка resume фикса (задача C)

Аналогично §3.3, но для `PLPlusFixer.fix_directory`:
1. Запустить фикс (rule-based или AI — уточнить, что именно прерываем).
2. Прервать на середине.
3. Запустить повторно.
4. Проверить: `skip_files` / `processed_files` работают, дублей нет.

> **СТОП-развилка**: аналогично §3.3 — если `skip_files` доступен только
> из GUI-обёртки, зафиксировать расхождение.
