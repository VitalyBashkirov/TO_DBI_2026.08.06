## 1. Цель

Два связанных дефекта:

1. **`scan_VVxVVx_*` при PlpCheck — пустой PLAN.**
   Причина (разведка DS_059): сканер выдаёт `plpcheck.BAD_PREFIX`, парсер ждёт `PlpCheck.STYLE.BAD_PREFIX.п.4.3`. Несовпадение → `has_rule() = False` → фикс не срабатывает → PLAN пуст.

2. **`scan_report_*` при v53 — PLAN = «Исправить по описанию».**
   Причина: `scanner._generate_plan` (2150–2196) — зашитая if-цепочка. Для v53 покрыто 4 правила из 332. Остальные → фолбэк.

**Решение:**
- **Маппинг кодов** `plpcheck.<NAME>` → `PlpCheck.*.<NAME>.п.*` в RuleEngine.
- **Унификация PLAN** — приоритет **действие из `ERROR`**; если `ERROR` не действие — `transform` + `example_out`.

## 3. Шаги

### 3.1. Маппинг кодов PlpCheck в RuleEngine

1. Найти в `rule_engine.py`: `has_rule(rule_code)`, `get_rule(rule_code)`, загрузку правил.
2. Добавить **маппинг**:
   ```
   plpcheck.<NAME>  →  PlpCheck.*.<NAME>.п.*
   ```
   Алгоритм:
   - если `rule_code` начинается с `plpcheck.`:
     - выделить `<NAME>`;
     - найти в правилах парсера запись, чей `rule_code` начинается с `PlpCheck.` и содержит `.` + `<NAME>` + `.п.`;
     - вернуть найденный `rule_code`;
   - иначе — вернуть исходный `rule_code`.
3. Применить маппинг в **обеих** функциях (`has_rule` и `get_rule`).
4. **Проверка:** для `plpcheck.BAD_PREFIX` → `has_rule() = True`.

### 3.2. Унификация PLAN в `scanner._generate_plan`

1. Найти `_generate_plan` (2150–2196).
2. **Приоритеты источника действия:**
   - **1.** Если `ERROR` начинается с глагола из **Приложения A** — использовать `ERROR` как действие.
   - **2.** Если `ERROR` начинается с **заглавной буквы**, содержит **глагол в первых 3 словах**, длина **< 200 символов**, и **не входит** в **Приложение B (исключения)** — считать действием.
   - **3.** Если `transform` + `example_out` присутствуют — вычислить:
     ```
     action = "Заменить " + rule.example_in + " на " + rule.example_out
     ```
   - **4.** Иначе — фолбэк **«Исправить по описанию»**.
3. **Формат PLAN:** `<CHECK> — <действие>`.
   Пример:
   ```
   bad_prefix — Переименовать в "v_iDp"
   v53.SQL.OUTERJOIN.п.1.1 — Заменить t1.id = t2.id(+) на left join t2 on t1.id = t2.id
   v53.STOR.SPEC_CHARS.п.2.10 — Исправить по описанию
   ```
4. **Спец-ветки** для PlpCheck (извлечение действия из `description`) — **сохранить**.
