# Промпт: сформировать файл "1.RUBRICATOR_FILES.md" - Рубрикатор: перечень файлов

Просмотреть каталог "F:\TO_DBI\DATA\CFT Platform IDE Documentation" без просмотра подкаталогов
в следующей очередности:
  имя файла,
  расширение .docx
  расширение .doc
  расширение .txt
  расширение .pdf
Если есть файлы с одинаковым именемя, в обработку брать первый файл. Со следующим по очереди файлом не работать.

В качестве примера работаем со следующим списком:
F:\TO_DBI\DATA\CFT Platform IDE Documentation\Рекомендации по адаптации кода на PLPlus для работы с DBI приложением v50.docx
F:\TO_DBI\DATA\CFT Platform IDE Documentation\Требования для совместимости кода с DBI.txt
F:\TO_DBI\DATA\CFT Platform IDE Documentation\Требования к локальным объектам и к коду - Дополнительные регламенты разработчика - Confluence.txt

На основании результатов сканирования создать текстовую таблицу 
1. Структура таблицы
|Колонка|Ширина     |Содержимое 
|-------|-----------|--------------------------------------------
|N      |2          |порядковый номер (1, 2, 3...)
|+/-    |2          |символ "+" или "-" (по умолчанию "+") 
|Код файла|14       |код файла (v50, тдс20240828, тклоик20240828) 
|Полное имя файла|не ограничена|полный путь к файлу 

Где "Код файла" из версии в имени файла или по первым буквам слов в имни файла + даты создания
 v50            для F:\TO_DBI\DATA\CFT Platform IDE Documentation\Рекомендации по адаптации кода на PLPlus для работы с DBI приложением v50.docx
 тдс20240828    для F:\TO_DBI\DATA\CFT Platform IDE Documentation\Требования для совместимости кода с DBI.txt
 тклоик20240828 для F:\TO_DBI\DATA\CFT Platform IDE Documentation\Требования к локальным объектам и к коду - Дополнительные регламенты разработчика - Confluence.txt

2. Заголовок и описание
- Первая строка: `# Рубрикатор: перечень файлов`
- Вторая строка с описанием поля"+/-": `#   "+/-" - Признак применения файла с правилами, где "+" - обрабатывать исправления, описанные в файле; "-" - не обрабатывать.`

3. Правила форматирования строк
Аналогичны примеру в таблице выше.
- Первый символ в строке `|`
- Первый символ в колонке с первой позиции в колонке
- Если значение для колонки пусто или больше ширины колонки, дополнять содержимое пробелами.
- Если значение для колонки больше ширины колонки, содержимое не обрезать. При этом ширину следующей колонки уменьшить на превышение в предыдущей.
- После каждой колонки ставится символ `|`
- Последний символ в сформированной строке - "|" не выводить. Ширину последней колонки не ограничивать

4. Принципы обработки
- Сохранить исходные значения (не изменять коды файлов и пути)
- Если какой-то файл отсутствует в исходных данных — не включать в результат
- Если значение `+/-` не указано — по умолчанию ставить `+`
