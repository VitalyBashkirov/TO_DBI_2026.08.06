## 4. Шаги

### 4.1. `code_in_comment` — отключить автофикс (B)

**Было (после D):**
```json
"transform_type": "regex",
"transform": "-- (удалено)"
```

**Стало:**
```json
"transform_type": "ignore"
```

**Плюс** — убрать `transform` **или** оставить как комментарий для справки:
```json
"note": "Удаление закомментированного кода — только вручную (риск удалить осмысленный текст)."
```

**Ожидаемый результат:**
- `code_in_comment` **попадает** в PLAN (`Удалить закомментированный код`);
- **автофикс не срабатывает** (не удаляет).

**Проверка:** при «Исправить код» — комментарии **остаются** на месте.

### 4.2. `bad_prefix_*` — разделить (C)

**Вернуть** `bad_prefix_*` к **исходному смыслу** — **только** плохие префиксы: `bad_`, `badprefix`, `tmp`, `temp`, `var`, `data`, `info`, `z_`, `x_`.

**4 паттерна** (по типам):

```json
{
  "name": "bad_prefix_varchar2",
  "regex": "\\b(bad|badprefix|tmp|temp|var|data|info|z_|x_)(\\w+)\\s+(varchar2|string)(\\s*\\(\\s*\\d+\\s*\\))?",
  "description": "Переменная varchar2/string с недопустимым префиксом",
  "transform_type": "regex",
  "transform": "v_{2} {3}{4}",
  "example_in": "bad_var varchar2(100);",
  "example_out": "v_var varchar2(100);"
}
```

**Аналогично** — `bad_prefix_number`, `bad_prefix_date`, `bad_prefix_boolean` (с `n_`, `d_`, `b_`).

**Ключевое:**
- regex **начинается** с `(bad|badprefix|tmp|...)` — **только** плохие префиксы;
- **не** матчит `Dp`, `Cnt` — это **зона** `missing_prefix_*`.

### 4.3. `missing_prefix_*` — доработать

**Оставить** как в D, но:

1. **Регистронезависимый lookahead:**
   ```
   (?i)(?!v_|p_|n_|d_|b_|cur_|gcur_|ret_|cn_|gcn_|lr_|lrec_|tb_)
   ```
   **Или** — `(?!v_|V_|p_|P_|...)`. **Рекомендую** `(?i)` — короче.

2. **Исключить параметры:**
   ```
   (?!\s+(in|out)\b)(?!\s+in\s+out\b)
   ```
   **Плюс** — исключить тип `[STRING_10]`, `[NUMBER]`, `[DATE]` (это ТБП, а не `varchar2`/`string`). **Но** — regex и так **не матчит** `[STRING_10]` (нет `varchar2`/`string`/...). **Оставить** как есть.

3. **`vDateRep` — не автофиксить** (B):
   - **добавить** lookahead `(?!v[A-Z]|p[A-Z]|n[A-Z]|d[A-Z]|b[A-Z])` — **не матчит** `vDateRep`, `pParam` и т.п.;
   - **если** нужно **пометить** в PLAN — **отдельный** regex с `transform_type: "manual"` (или `ignore`).

   **Минимальное решение:** lookahead — и **не** автофиксить.

### 4.4. Доп. правило 1 — регистронезависимость

**Во всех** паттернах `bad_prefix_*` и `missing_prefix_*`:
- **либо** `(?i)` в начале regex;
- **либо** явные `v_|V_|p_|P_|n_|N_|d_|D_|b_|B_|cur_|CUR_|...`.

**Рекомендую** `(?i)`.

### 4.5. Доп. правило 2 — исключить параметры

В `missing_prefix_*` **добавить**:
```
(?!\s+(in|out)\b)
```

**Плюс** — в `bad_prefix_*` — **то же** (если параметр с плохим префиксом — **не** фиксить авто).

**Ожидаемый результат:** `P_PARAM in [STRING]` — **не** матчится.
