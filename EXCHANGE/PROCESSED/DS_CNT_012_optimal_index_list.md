# Запрос KODA: оптимальный список для индексации CNT

## Контекст
Проект TO_DBI. Свой индексатор (DS_CNT_005c) — пакетный семантический
поиск по F:\TO_DBI через Ollama (nomic-embed-text). Назначение —
помощник CNT (Ai-Continue) и оператора: быстро находить нужные
документы, регламенты, отчёты.

Текущий `.continueignore`:
- исключает: .git\, logs\, PATCH_IN\, PATCH_OUT\, SRC\, .kilo\,
  .vscode\, reports\, temp\, node_modules\, __pycache__, *.pyc, *.log;
- исключает подкаталоги EXCHANGE\ (AI_IN, AI_OUT, INBOX, OUTBOX,
  PROCESSED и т.д.);
- индексирует корень F:\TO_DBI, DATA\, корень EXCHANGE\, tools\.

## Вопрос
Какой **оптимальный** список каталогов / подкаталогов / файлов
индексировать для CNT?

Учти:
1. CNT = Ai-Continue, помощник в редакторе (Chat/Edit/Apply/Autocomplete).
2. Индексатор — пакетный (ночной), rate limit 1 req/sec, ~1000 файлов
   = ~5 часов.
3. Цель — **релевантный поиск** по документам, регламентам, стандартам.
4. Мусор в индексе ухудшает качество (проверено: «матрица доступа»
   не находит SEC_POLICY_AI.md, если в индексе .kilo\, SRC\, reports\,
   temp\).
5. Есть каталоги:
   - `DATA\` — документация, рубрикаторы, дорожные карты;
   - `EXCHANGE\` (корень) — регламент, политика ИБ, стандарт DS,
     контекст, шаблоны;
   - `EXCHANGE\<подкаталоги>\` — обменные (AI_IN, AI_OUT, INBOX,
     OUTBOX, PROCESSED) — **не индексировать**;
   - `tools\` — скрипты, модули индексатора;
   - `SRC\` — исходники — **не индексировать**;
   - `PATCH_IN\`, `PATCH_OUT\` — данные CFT — **не индексировать**;
   - `logs\` — логи — **не индексировать**;
   - `.kilo\`, `.kilocode\`, `.vscode\`, `reports\`, `temp\` —
     служебные — **не индексировать**.
