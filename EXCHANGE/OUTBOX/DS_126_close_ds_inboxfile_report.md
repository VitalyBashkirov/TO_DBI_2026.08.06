## Ключевой инцидент чата 22

### Симптом

close_ds.ps1 запускался через PS 5.1 -> 5 ложных ошибок парсинга
на L79, L85, L201, L204 («Непредвиденная лексема }»).
В сообщении об ошибке кириллица отображалась как кракозябры:
"BOM-check СЃРѕР·РґР°РЅРЅС‹С… С„Р°Р№Р»РѕРІ:".

### Ошибочные гипотезы (отвергнуты)

1. LF вместо CRLF -> нормализация в CRLF не помогла.
2. [Parser]::ParseFile ненадёжен -> ParseInput давал 0 ошибок.
3. Битый текст -> hex чист, баланс скобок/кавычек OK.

### Настоящая причина

PowerShell 5.1 при запуске .ps1 БЕЗ BOM читает файл в системной
ANSI-кодировке (CP1251 на русской Windows). UTF-8 байты кириллицы
интерпретируются как CP1251 -> кракозябры -> парсер видит
искажённые строки -> ложные ошибки.

Диагностика: L204 через Get-Content default = кракозябры;
через Get-Content -Encoding UTF8 = корректно.

### Решение

Запись close_ds.ps1 С BOM. После этого:
- L204 через Get-Content default -> корректно.
- AST ParseFile -> 0 ошибок.
- Боевой запуск -> работает без ошибок парсинга.

Зафиксировано как Урок I (п.6 §6.2.1 и §6.1).
