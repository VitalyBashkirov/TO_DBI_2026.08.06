## НОВЫЕ ПРАВИЛА (действуют с чата 23)

### Правило N1: шапка PS-блока

Каждый блок PS начинается с:

    cls
    Set-Location -LiteralPath 'F:\TO_DBI'
    [Console]::OutputEncoding = [System.Text.Encoding]::UTF8
    $OutputEncoding = [System.Text.Encoding]::UTF8
    chcp 65001 | Out-Null
    cls

Первый cls — затирает предыдущий вывод PS ДО старта блока.
Второй cls — затирает «Active code page» от chcp.
Экран чистый: пользователь видит задание + лог выполнения.

Уточнение правила 0 регламента: cls идёт ПЕРЕД Set-Location.

### Правило N2: логирование PS-блоков

Каждый блок PS пишет лог через Start-Transcript в F:\TO_DBI\PS\.
Перед записью нового лога — все *.log в PS\ удаляются:

    $logDir = 'F:\TO_DBI\PS'
    if (-not (Test-Path $logDir)) { New-Item -ItemType Directory -Path $logDir | Out-Null }
    Get-ChildItem -Path $logDir -Filter '*.log' -File -ErrorAction SilentlyContinue | Remove-Item -Force -ErrorAction SilentlyContinue
    $ts = Get-Date -Format 'yyyyMMdd_HHmmss'
    $logFile = Join-Path $logDir "ds<XXX>_<этап>_$ts.log"
    Start-Transcript -Path $logFile -Force | Out-Null
    # ... команды ...
    Stop-Transcript | Out-Null

Файл лога перетаскивается в чат DeepSeek вместо копирования вывода.
Каталог PS\ — в .gitignore, не часть репозитория.
Зафиксировано в DS_STANDARD.md §6.6.

### Правило N3: -replace в PS — regex, не строковая замена

-replace интерпретирует паттерн как regex. Спецсимволы (%, {}, ())
требуют экранирования. Для простых строковых замен использовать
.Contains() / .Replace() (методы String) — они НЕ интерпретируют
regex.

Получено при попытке отката rule_based_fixer.py L305: -replace
с [regex]::Escape не сработал, .Replace() сработал.

### Правило N4: стартовые файлы чатов — сразу в файл

Стартовый файл следующего чата формируется СРАЗУ через
PowerShell-блок (создание файла NN.Старт.txt в F:\TO_DBI\).
Не через Text Copy Download — сразу в файл.

## Уроки чата 23 (в DS_STANDARD.md §6.2.1)

### Урок J: $matches в PowerShell — Hashtable, не массив

- $matches[0] — вся строка.
- $matches[1..n] — нумерованные группы (нумерация с 1).
- $matches[3] в -f-форматировании — НЕ работает как индекс группы.
- ПРАВИЛЬНО: именованные группы (?<name>...) + $($matches['name']).
- ОПАСНОСТЬ: при ошибке форматирования в ForEach-Object строка
  может бесследно исчезнуть из потока.
- Всегда проверять «Строк до / после».

Пример:
  ПЛОХО: "[{3}-{2}-{1}]" -f $matches[3], $matches[2], $matches[1]
  ХОРОШО: "[$($matches['y'])-$($matches['m'])-$($matches['d'])]"

### Урок K: аудит источника, не только симптома

Перед «нормализацией» данных (например, bot.log) — найти всех
писателей. Если источник жив, аномалии накапливаются снова.

Пример DS_128: план «нормализовать 35 строк без timestamp» был
неполным. Аудит выявил 8 мест в 6 файлах. Миграция источника —
в DS_129.

### Урок L: -replace в PS — regex, не строковая замена

См. Правило N3.

### Урок M: глобальный -replace без указания строки

-replace заменяет ВСЕ вхождения в файле. Если в файле два разных
места с одинаковым паттерном, но разным назначением (L66 bot.log
и L305 AI_RESPONSE), -replace заменит оба. Нужно либо ограничить
контекст, либо использовать построчную обработку с проверкой
номера строки.

- Проверять, не занят ли номер DS_XXX.
- Имя DS — явно отражает действие.
- Простые одношаговые DS — вручную PowerShell.
- При ручном выполнении DS — файлы задания/отчёта постфактум.
- INBOX-гигиена — использовать -InboxFile в close_ds.ps1.
- Плоский формат для тел заданий (без вложенных ```) — §3.2.
- .Replace() вместо -replace для простых строковых замен.
- Не забывать: глобальный -replace без указания строки — опасно.
- Стартовые файлы чатов — формировать сразу в файл.
