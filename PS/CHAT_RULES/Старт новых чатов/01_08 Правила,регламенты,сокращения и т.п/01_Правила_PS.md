## 9. EAP=Continue на pytest-блоки (чат 59)

Пример:
```powershell

$ErrorActionPreference = 'Continue'
try {
    & $python -m pytest ... 2>&1 | Out-File -FilePath $out -Encoding utf8
    $rc = $LASTEXITCODE
} finally { $ErrorActionPreference = $oldEAP }
```

## 63_1. Get-Content -Encoding UTF8 на без-BOM кириллице врёт (чат 63)
PS 5.1 читает UTF-8 файл **без BOM** как ANSI -> кириллица превращается в
кракозябры при `Get-Content -Encoding UTF8`. Сама запись через
`[System.IO.File]::WriteAllText(..., UTF8Encoding($false))` корректна —
проблема только в чтении-для-показа.
Решение: для проверки без-BOM файлов с кириллицей — только
`[System.IO.File]::ReadAllText($path, [System.Text.Encoding]::UTF8)`.
`Get-Content` годится для BOM-файлов, ASCII, чисел.
BOM-детект: первые 3 байта через `[System.IO.File]::OpenRead`; BOM = (EF BB BF).
См. также 61_4; в `.ps1`, вставляемый через консоль, примеров-кракозябр избегать.

## 64_4. BOM / кодировка по расширению — сводная таблица (чат 64)

PS 5.1 при -File читает .ps1 БЕЗ BOM как ANSI: кириллица превращается

Кодировка записи зависит ОТ РАСШИРЕНИЯ:

| Расширение | BOM | Кодировка | Правило |
|---|---|---|---|
| .ps1 (с кириллицей) | ДА (EF BB BF) | UTF-8 BOM | 64_4 |
| .ps1 (только ASCII) | можно без, но с BOM безопаснее | UTF-8 | 64_4 |
| .py (с кириллицей) | ДА | UTF-8 BOM | 6at-1, 64_4 |
| .py (только ASCII) | без | UTF-8 | 6at-1 |
| .md | НЕТ | UTF-8 no-BOM | 11, 63_1, 64_4 |
| .txt (отчёты, старты) | НЕТ | UTF-8 no-BOM | 11, 13, 64_4 |
| .json | НЕТ | UTF-8 no-BOM | 11, 64_4 |
| msgfile (git commit -F) | НЕТ | UTF-8 no-BOM | 11, 64_4 |

Проверка для .ps1/.py:
  $b = [System.IO.File]::ReadAllBytes($p)
  $isBom = ($b.Length -ge 3 -and $b[0] -eq 0xEF -and $b[1] -eq 0xBB -and $b[2] -eq 0xBF)
Проверка для .md/.txt/.json/msgfile: $isBom должно быть $false.

Практика:
  UTF8Encoding($true)  — BOM  (.ps1/.py с кириллицей)
  UTF8Encoding($false) — no-BOM (.md/.txt/.json/msgfile)

## 64_10. Удаление нулевых логов — не трогать активный Start-Transcript (чат 64)

## 68_1. throw в PS 5.1 — только внутри try/catch/finally (чат 72)

Подтверждено зондом (chat72_01_probe_A/B/C):
- **throw вне try/catch** — при `powershell -File` **прерывает** дочерний процесс (rc≠0, зонд A: rc=-1). В **построчной интерактивной вставке** по отчёту 71 предохранитель сработал вхолостую; прямым зондом 72 это **не перепроверялось** — на throw вне try не полагаться.
- **throw внутри try + finally (без catch)** — `finally` выполняется, throw пробрасывается (rc≠0, зонд C: rc=-1), код после блока **не** выполняется. **Рекомендуемый предохранитель:** гарантирует Stop-Transcript/очистку и корректно валит скрипт.
- **throw внутри try/catch/finally** — `catch` поглощает, `finally` выполняется, код после блока выполняется. Для «мягкой» обработки ошибок.

Правило: критичные предохранители (нет файла, пустой исходник, неизвестный хост) — **всегда** внутри `try/finally`, при необходимости с `catch`. `throw` без обрамления в многострочных PS-блоках не использовать.

Эталон: `chat72_01_probe_B.ps1`, `chat72_01_probe_C.ps1`.

**Живой инцидент (чат 72, шаг 72_02b):** `throw` вне try/catch после неудачной AST-проверки **не остановил** последующую `WriteAllText($test, …)` — тест был записан, хотя проверка провалилась. С тех пор критичные предохранители оборачиваются в `try { … } catch { … } finally { … }`; `throw` внутри try/catch гарантированно прерывает текущий блок, а `catch` решает — валить скрипт дальше (`throw` из catch) или продолжить.

## 65_3. BOM при правке существующих .py: сохранять исходный формат файла (чат 73)

Живой инцидент 73_02b_v4 -> 73_02c:

## 64_11. Обрамление PS-сеанса: первая — Clear-Host, последняя — полное имя лога зелёным (чат 74)

Любой `.ps1` (и консольный стартовый блок, 65_2) **начинается** командой `Clear-Host` и **заканчивается** командой `Write-Host "LOG: <полный_путь_к_логу>" -ForegroundColor Green`.

- `Clear-Host` — самая первая исполняемая команда, **до** кодировок (60_1), `Stop`, `Start-Transcript`. Цель: лог начинается с чистого экрана (64_3).
- `Write-Host "LOG: ..."` — самая последняя исполняемая команда, **после** `Stop-Transcript`, очистки нулевых логов (64_10), любых `Write-Host`-итогов. Паузы нет (10).
- В строке — **полный путь** к файлу лога, не только имя. Цвет — `Green`.
- Между ними — всё тело. После `Write-Host "LOG: ..."` команд нет.
- Если скрипт упал — `finally` всё равно печатает `LOG: ...` зелёным (68_1).

Эталон: `chat74_00_regress.ps1`, `chat74_01_guicheck.ps1`.
## 64_12. Без `exit $rc` в конце PS-скрипта (чат 74)

В конце `.ps1` **не использовать** `if ($rc -ne 0) { exit $rc }` и аналогичные `exit`.

- Скрипт завершается сам (10); `finally` гарантирует `Stop-Transcript` и `Write-Host "LOG: ..." -ForegroundColor Green` (64_11).
- Успех/сбой — по `ERROR:` в логе, `git add/commit/push rc=...`, `git status -sb` без `[ahead N]`, `git log -1 --oneline`.
- `` — внутренняя для `try/catch`/откатов; наружу через `exit` не выводится.
- Причина: `exit` конфликтует с `finally` (68_1), ломает `OUTER_RC`.

Эталон: `chat74_06_all.ps1`.
## 64_13. Единственный способ создания `.ps1`/`.py` — генерация PS-кодом (чат 74)

Любой `.ps1`/`.py` создаётся **только** PS-скриптом через `WriteAllLines`/`WriteAllText` (64_1 п.1-4, 65_2). **VS Code, Блокнот, копирование из чата — не используются ни при каких обстоятельствах**, включая обход зависания (73_00, 73_02b, 74_03, 74_05).

- **Генератор** — `.ps1` в `Скрипты чатов\`, UTF-8 **BOM** (64_4).
- **Тело** — `List[string]` + `.Add('...')`, одна строка файла на элемент (61_7); `WriteAllLines` последней после проверок (64_2).
- **BOM** после записи: `EF BB BF` для `.ps1`/`.py`; нет — для `.md`/`.txt`/`.json`/msgfile (64_4).
- **Запуск** — `& powershell -NoProfile -ExecutionPolicy Bypass -File <target>` (65_2); в консоли — **одна строка**.
- **Разрыв курицы-яйца** — «нулевой» генератор пишется **консольным** `WriteAllLines` массивом (65_2), не редактором; вложенные кавычки — `'` (7/61_5), here-string в консоли **запрещён**.
- **Зависли** (`>>`) — `Ctrl+C` → `Test-Path` → **повторная генерация**; VS Code/Блокнот **запрещены**.

Эталон: `chat74_06_all.ps1`.
## 64_14. Генерация .ps1 и запуск - одним блоком с Test-Path (чат 74)

Любой шаг, создающий .ps1, **обязан** содержать в **одном** консольном блоке: (1) WriteAllLines массивом; (2) Test-Path целевого файла **одной строкой**; (3) & powershell -File <target> - **только** если Test-Path = True.

- if/elseif/else на верхнем уровне консоли **запрещены** (64_15); проверка - Test-Path **одной строкой**, решение - глазами.
- Живой инцидент 74_09: -File на несуществующий .ps1 - The argument does not exist.

Эталон: chat74_09_all.ps1.
## 64_15. В консольном блоке - без if/elseif/else на верхнем уровне (чат 74)

В **консольной** вставке PS 5.1 if/elseif/else, try/finally, foreach на верхнем уровне **рвутся** (73_00, 74_09: elseif/else вне if - CommandNotFoundException).

- В консоли - **только** WriteAllLines массивом + Write-Host GEN OK. Проверки - Test-Path **одной строкой** (64_14).
- Все if/else - **внутри** .ps1 (try/catch/finally, 68_1).

Эталон: chat74_09_all.ps1.
