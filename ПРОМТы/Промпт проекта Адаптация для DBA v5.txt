Ниже новый промт. Поищи неточности и ошибки. Оптимизируй с точки зрения постановки задачи и количества используемых токенов.
-----------------
Сопровождаем АБС "ЦФТ-Банк". 
АБС работает с Oracle на Платформе 1.
Требуется перейти на Платформу 2MCA DBI (PostgreSQL).

Разработай АРМ "Адаптация под DBI" v.03

Проект для АРМа в папке F:\TO_DBI со следующей структурой:

    F:\TO_DBI\
    ├── DATA\              # Исходные данные (только для чтения)
    │   ├── patch_WORK\    # Локальный функционал для миграции (имя каталога с преффиксом patсh* может менятся)
    │   ├── patch_WORK.pck # .pck-файл с перечнем для экспорта импорта объектов в АБС (имя с преффиксом patсh* может менятся)
    │   ├── CFT Platform IDE Documentation\ # Документация с рекомендации, требования, регламенты, инструкции и т.п.
    │   └── ПОМПТы\        # Файлы с промтами типа "Адаптация под DBA vXXXX.txt (где vXXXX - версия промпта может менятся)
    │
    ├── SRC\               # Каталоги для разрабатываемого функционала, AI документации проекта, каталога логов. Сам АРМ и настройки АРМа на уровне X:\TO_DBI\SRC
    │   ├── analyzer\      # Анализ PLPlus-кода
    │   ├── fixer\         # Автоматические исправления
    │   ├── utils\         # Утилиты
    │   └── AI_DOCS\       # Сгенерированная AI документация (руководства, описания проекта, инструкции и т.п.)
    │
    └── NEW_DATA\          # Результат миграции (откорректированный код)
        └── logs\          # Каталог для логов
 
Используй версии документации для обучения AI
и генерации меток в сгенерированных выходных файлах:

Версии документации обычно "зашиты" в именах файлов и могут меняться:
 -v50 (пятидесятая версия "Рекомендации по адаптации кода на PLPlus для работы с DBI приложением v50.docx");
 -тдс20240828 (версия тдс от 28.08.2024 "тдс20240828.Требования для совместимости кода с DBI.pdf")
 -тклоик20240828 (версия тклоик от 28.08.2024 "тклоик20240828.Требования к локальным объектам и к коду - Дополнительные регламенты разработчика - Confluence.pdf")
 и т.п.

Описание языка PL+: 
    X:\TO_DBI\DATA\CFT Platform IDE Documentation\CFT Platform IDE Documentation.docx 
    Приложение 3. Описание PL/Plus

Инструменты разработки:
    - VS Code — редактор
    - PowerShell
    - CFT Platform IDE — Check DBI (Ctrl+D, A) для проверки
    - Python 3.12+
    - Tkinter + Python .exe

Примеры маркировки исправлений:
    --v50 п.1.1,п.1.2,п.3.5
    --тдс20240828 п.1,п.2,п.3
    --тклоик20240828 ОТЧЁТЫ.п1, ПРЕДСТАВЛЕНИЯ.п.3,п.7 КОДИРОВАНИЕ.п.2,п.3
    и т.п.

Задачи:
1. Изучи новую документацию в X:\TO_DBI\DATA\CFT Platform IDE Documentation\и обновленную структуру проекта.
2. Запускай только последнюю версию промта.
3. Анализируй папку проекта X:\TO_DBI. Если каких то каталогов не хватает, добавь.
4. Создай документацию проекта, Пользовательские инструкции "АРМ Адаптация под DBI. Руководство Пользователя vXXXX.txt" и т.п.
   Размещай их в каталоге X:\TO_DBI\SCR\AI_DOCS
   Маркируй версии AI-докуметации и АРМа с добавлением номера версии где XXXX номер версии.
5. Интерфейс АРМа классический:
   Переменные на форме:
   Каталоги: (Беруться по умолчанию из структуры проекта и сохраняются в виде настроек в X:\TO_DBI\SCR\. Следующий запуск, каталоги подтягивать из сохраненных настроек)
    Корневой каталог с исходными файлами (Пример: F:\TO_DBI\DATA\patch_WORK\src):
     Варианты:
     (*) сканировать подкаталоги для поиска файлов по шаблону и возможностью фильтрации файлов по шаблону (Пимер: *.plp):
     или
     ( ) только указанный каталог
    Каталоги для файлов с результатами (Должен автоматически увелививать номер итерации в имени каталога. Пример: F:\TO_DBI\DATA_NEW\patch_WORK.XXXX)
     Варианты:
     (*) сохранять только файлы, которые будут откорректированы
     или
     ( ) созранять все файлы, указанные в шаблоне для исходных
     Варианты:
     (*) итоговый файл распологать в корне X:\TO_DBI\NEW_DATE\patch_WORK\
     или
     ( ) копировать структуру каталога расположения исходного файла
    Алгоритмы. Учитывать:
     (V) Рекомендации по адаптации кода на PLPlus для работы с DBI приложением
     (V) Требования для совместимости кода с DBI
     (V) Требования к локальным объектам и к коду - Дополнительные регламенты разработчика
     (Пользователь должен указать хотя бы одно требование, рекомендацию)
    Маркировка и комментарии изменений в выходных файлах:
      При исправлении, в файлы с результатами миграции добавляй:
      (V) Перед откорректирваной строкой (или блоком кода)  Маркировку;
      (V) На следующих строках закомментированый предыдущий вариант;
      (V) На следующей, исправленный код с комментарием, что исправлено (в конце строки или перед исправленной строкой, если описание больше 60 символов)
    Логи:
     Каталог для логов
      Варианты:
      (V) логировать в разрезе требований
      (V) логировать в разрезе исходного файла
     Рядом с окном логов добавь кнопку "Очистить".
   Общие требования:
   При "наезде" мышки на кнопку формы должна высвечиваться подсказка с полным наименованием и описанием ее назначения.
   Кнопка должна быть не доступна, если предыдущие действия выполнены не корректно.

6. Разработай скрипты с использованием переменных на экранной форме АРМа:
6.1.Cкрипт анализа проблемных конструкций в исходных файлах 
6.2.Скрипт автоматического исправления кода с маркировкой исправлений и комментариями
7. АРМ должен показывать индикацию прогресса выполнения задачи.
