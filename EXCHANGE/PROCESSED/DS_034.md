Проверка регулярного выражения в интерактивной консоли Python:

python
import re
line = "dp   integer:=0;\t\t\t--управление debug_pipe"
match = re.search(r'^\s*(\w+)\s+(string|number|integer|varchar2|date|ref|rowtype|boolean|timestamp)\s*(?:\([^)]*\))?\s*(?::=|;)', line, re.IGNORECASE)
print(match)
# Должно быть: <re.Match object; span=(0, 14), match='dp   integer:='>
if match:
    print(f"var_name={match.group(1)}, var_type={match.group(2)}")
    # var_name=dp, var_type=integer
Если match is None — паттерн не работает, нужно его исправить.

Возможная проблема: в файле могут быть табы между именем и типом, а не пробелы. \s покрывает и табы, так что должно работать. Но если между integer и := стоит 0, а паттерн ожидает : или ; — не сработает.

Смотрим на реальную строку:

text
dp   integer:=0;
dp → \w+ ✓
 (пробелы) → \s+ ✓
integer → (string|number|integer|...) ✓
: (перед =) → \s*(?::=|;) — паттерн ожидает : или ; сразу после опциональных пробелов. Здесь : есть ✓
=0; — не важно, паттерн не якорится на конец.

Но! Паттерн \s*(?::=|;) — \s* съест пробелы, потом : — но : идёт сразу после integer, без пробела. \s* съест 0 пробелов, потом (?::=|;) — : матчится. ОК.

НО: паттерн не якорится на $. Значит, он найдёт совпадение в любом месте строки. Это может привести к ложным срабатываниям внутри выражений. Например, строка:

text
x := some_string_value;
может матчиться как var_name = some_string_value? Нет, some_string_value не является типом. Но string внутри some_string_value — да, \b нет в паттерне, но (string|...) требует, чтобы перед ним был \s+ (пробелы). Значит, _value перед string — это _, не пробел. Не сработает.

Однако паттерн может сработать на строке:

text
if some_var is string then
Здесь some_var → \w+, потом is — но is не является типом. А string — да. Но перед string стоит пробел. Тогда some_var → \w+, \s+ — is даёт \s+ только один раз перед some_var? Нет, some_var\s+is — is не тип, паттерн требует (string|...). Значит, some_var\s+is не матчится. А is string — тогда is → \w+, \s+, string → тип. Совпадение! var_name = is, var_type = string. Это ложное срабатывание.

Нужно добавить якорь ^ (уже есть) + проверку, что var_name не является ключевым словом — это уже есть через excluded.

Но is не в excluded в текущем коде. Нужно добавить.
