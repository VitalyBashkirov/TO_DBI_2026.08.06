# Промпт: создать рубрикатор в виде трёх текстовых файлов-таблиц
## Задача
На основе предоставленных документов создать три файла в формате Markdown:
1. `1.RUBRICATOR_FILES.md` — перечень файлов с инструкциями, рекомендациями, регламентами, требованиями.
2. `2.RUBRICATOR_CATEGORIES.md` — группировка исправлений по категориям.
3. `3.RUBRICATOR_FIXES.md` — полный перечень требуемых исправлений.

## Требования к оформлению таблиц
- Использовать выравнивание: левое (`---`) для всех колонок (символ `:` в строке разметки НЕ ИСПОЛЬЗОВАТЬ).
- ЖЕСТКО соблюдать ширину колонок (символов):
  - N: 3
  - Признак: 8 (`+` действующий, `-` нет)
  - Код файла: 16
  - Полное имя файла: 124
  - Код категории: 14
  - Описание категории: 120
  - КодыФайла.Категории.Исправления.Пункты/Строки: 42
  - Пункт(ы) документации: 10 (если пункт не определён — пробелы; для `п.22, 23` писать `п.22,23`)
  - Строки документации: 10 (если заполнен `Пункт(ы)` — не заполнять; для v50 всегда пустая)
  - Короткое описание: 50 (ОБЯЗАТЕЛЬНО добивать пробелами справа до 50 символов)
  - Подробное описание: 80–1024 (ширина не ограничена)
- Последний символ в строках таблиц `|` не нужен.
- Значения полей начинаются с первого символа (пробел перед значением НЕ СТАВИТЬ).
- Если длина значения меньше ширины колонки — дополнить пробелами СПРАВА.
- Если длина значения превышает ширину колонки — можно увеличить ширину этой колонки, но тогда уменьшить ширину следующей.
- **Запрещено использовать обратные кавычки (бэктики) внутри значений полей** — заменять на одинарные кавычки `'`.
- **Кавычки-ёлочки `«»` заменять на обычные двойные кавычки `"`.**
- **При сокращении текста для колонки «Короткое описание» нельзя обрезать слово посередине или нарушать грамматику.** Если текст не влезает в 50 символов, сокращайте осмысленно, сохраняя окончания и падежи.
- При формировании заголовка, если длина меньше допустимой — дополнить пробелами справа. Если больше — остаток переносить на вторую строку заголовка с соблюдением разметки предыдущих колонок.

## Файл 1: `1.RUBRICATOR_FILES.md`
### Структура таблицы
| N | Признак | Код файла | Полное имя файла |

## Файл 2: `2.RUBRICATOR_CATEGORIES.md`
### Структура таблицы
| N | Код категории | Описание категории |

## Файл 3: `3.RUBRICATOR_FIXES.md`
### Структура таблицы
| N | КодыФайла.Категории.Исправления.Пункты/Строки | Пункт(ы) | Строки | Короткое описание | Подробное описание

### Правила формирования кода исправления
Формат: `Код_файла.Код_категории.Код_исправления.Диапазон_строк`
- `Код_файла`: v50, тдс20240828, тклоик20240828
- `Код_категории`: SQL, STOR, PROC, INT, CACHE, DEV, LOCAL
- `Код_исправления`: краткое название латиницей (OUTERJOIN, ROWNUM, DECODE и т.п.)
- `Пункт(ы)`: п.1.1, п.1.2, п.22,23 (без пробелов после запятой)
- `Диапазон_строк`: стр.12 или стр.12-13 (для v50 не заполняется)

**Примеры:**
- `v50.SQL.OUTERJOIN.п.1.1`
- `v50.SQL.ROWNUM.п.1.2`
- `тдс20240828.SQL.ANSI_JOIN_ANNOTATION.стр.3-4`

### Специальные правила замены для `тклоик20240828`
- `"FTC_"` заменить на `"PSH_"`
- `"ЦФТ"` заменить на `"Банка"`
- `"префикс банка"` заменить на `"префикс банка [ПСБ]"`

### Важное требование к колонке «Короткое описание»
**Каждое значение в колонке «Короткое описание» должно быть ровно 50 символов.**
- Если текст короче 50 символов — дополнить пробелами СПРАВА.
- Если текст длиннее 50 символов — сократить, сохраняя грамматику (не обрезать слова, не нарушать падежи).
- Значение должно начинаться с первого символа (без ведущего пробела).

### Важное требование к колонке «Подробное описание»
- Значение должно начинаться с первого символа (без ведущего пробела).
- Запрещены обратные кавычки (бэктики) — заменять на одинарные кавычки `'`.
- Кавычки-ёлочки `«»` заменять на обычные двойные кавычки `"`.

### Общий поток
Файл `3.RUBRICATOR_FIXES.md` не разбивать на части по документам — все исправления идут одним потоком, сквозная нумерация.

## Требования к выводу
1. Выдать три файла целиком в формате Markdown.
2. Кодировка: UTF-8.
3. Разделители в таблицах: `|`.
4. Нумерация строк в таблицах сквозная в пределах каждого файла.
5. Колонки должны быть выровнены для читабельности (см. ширину выше).
6. Последний символ `|` в строках таблиц не нужен.
7. Если какие-то файлы не предоставлены — сообщить.
