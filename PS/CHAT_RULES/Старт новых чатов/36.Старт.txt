### §6.6.25 — удалять временные файлы PS\ в том же блоке

**Правило:** временные `.py`-файлы в `PS\` (`_patch_*.py`, `_diag*.py`,
`_check*.py`, `_smoke*.py`, `_parse*.py`, `_d*.py`, `_g*.py`) должны
удаляться **в том же PS-блоке**, где создаются, сразу после использования.

Итоговое содержимое `PS\` после блока — только `<имя_блока>.log` и `persist\`.

**Инцидент чата 35:** после блока №8а в `PS\` накопилось 8 временных
файлов + 2 лога. Обнаружено пользователем.

### Урок чата 35 (предложение зафиксировать в §6.6.26)

При патче кода через Python-скрипт: **якорь должен быть уникальной подстрокой
из реального файла**, а не «по памяти». Регистр (`# Проверка` vs `# проверка`) —
частая причина провала assert. **Всегда сначала диагностика `repr()` якорей.**

Инцидент: `_patch_deep2.py` упал на `# проверка расширения` (строчная «п»),
в файле было `# Проверка расширения` (заглавная «П»).

### Урок чата 35 (предложение зафиксировать в §6.6.27)

Патч из нескольких правок: **каждая правка = отдельный файл + отдельный write
+ удаление**. Если assert падает — падает одна правка, а не все пять.

Применено в `N8a-fix` (5 отдельных `_d1.py`..`_d5.py`) — сработало.

### Here-string > 100 строк + вложенные Python-строки — гарантированно ломают PS 5.1

Правило чата 34:
- 1 here-string ≤ 60 строк контента.
- Не вкладывать Python-строки в тройных кавычках внутрь PS here-string.
- Если нужно записать длинный Python-скрипт — разбить на 2-3 блока,
  писать в отдельные .py, потом AppendAllText или склеивать.

### git diff / git diff --stat — только через | Out-Host

Правило §6.6.1: git diff ... | Out-Host
гарантирует попадание вывода в Start-Transcript. Без | Out-Host —
буферизация, пустой лог.

## Вывод в PS и логи — правила чата 34/35

### Принципы

1. Строки типа Лог: <путь> — зелёным: Write-Host "Лог: $log" -ForegroundColor Green.
2. Ошибки — красным: Write-Host "FAILED" -ForegroundColor Red.
3. Заголовки секций — Cyan: Write-Host "=== ... ===" -ForegroundColor Cyan.
4. Итоговый статус (OK) — зелёным: Write-Host "OK" -ForegroundColor Green.
5. Данные (таблицы, git diff) — через | Out-Host.
6. Кириллица в Python-print через cp866-консоль — кракозябры (§6.6.21),
   данные в файле корректны, не влияет на результат.
7. **Для Python inline-команд с `$` внутри строки — использовать here-string `@'...'@`,
   писать в .py, запускать `python file.py`.** Иначе PS 5.1 парсит `$` как переменную.
   Инцидент чата 35: `print('~$:', ...)` → ParserError InvalidVariableReference.
8. **Stop-Transcript | Out-Null в конце КАЖДОГО блока** — иначе `.log` остаётся 0 байт.
   Инцидент чата 35: `ds145_impl_a_fix.log` 0 байт, `ds145_impl_b.log` 0 байт.

### Типовой шаблон блока

~~~powershell
# ============================================================
# N1. <Название блока>
# Дата: YYYY-MM-DD
# Назначение: <что делаем>
# Ожидание: <что должно быть>
# Риски: <что может пойти не так>
# ============================================================

$ErrorActionPreference = 'Continue'
$proj = 'F:\TO_DBI'
Set-Location $proj

# N7 v7: очистка PS\ (сохраняя persist\)
if (Test-Path "$proj\PS") {
    Get-ChildItem "$proj\PS" -Exclude 'persist' -ErrorAction SilentlyContinue |
        Remove-Item -Recurse -Force -ErrorAction SilentlyContinue
} else {
    New-Item -ItemType Directory -Path "$proj\PS" | Out-Null
}
if (-not (Test-Path "$proj\PS\persist")) {
    New-Item -ItemType Directory -Path "$proj\PS\persist" | Out-Null
}

$log = "$proj\PS\<имя_блока>.log"
Start-Transcript -Path $log -Force | Out-Null
$env:PYTHONIOENCODING = 'utf-8'
chcp 65001 | Out-Null
$utf8NoBom = New-Object System.Text.UTF8Encoding($false)

# ... работа ...

Write-Host "`n=== Секция ===" -ForegroundColor Cyan
<команда> 2>&1 | Out-Host

Write-Host "`nOK" -ForegroundColor Green
Write-Host "Лог: $log" -ForegroundColor Green

Stop-Transcript | Out-Null
~~~

### Что НЕ делать

- Не использовать return в ручных блоках (правило №19), кроме fail-fast
  в if-ветке ошибки (§6.6.3).
- Не полагаться на $LASTEXITCODE после Select-String (правило №22).
- Не читать .log через Get-Content в PS 5.1 (§6.6.15) — только через Python
  с encoding='utf-8'.
- Не использовать -like для подстроки (§6.6.9) — использовать .Contains().
- Не использовать Add-Content -Encoding UTF8 в PS 5.1 (§6.6.20) — только
  [System.IO.File]::AppendAllText с UTF8Encoding($false).
- Не использовать Out-File -Encoding UTF8 для .py — даёт BOM.
  Использовать [System.IO.File]::WriteAllText с UTF8Encoding($false).

### Кодировки

- .py / .md / .json / .ini / .sql — UTF-8 БЕЗ BOM (§6.1).
- .ps1 с кириллицей — UTF-8 С BOM.
- Все файлы через [System.IO.File]::WriteAllText или AppendAllText
  с UTF8Encoding($false).
