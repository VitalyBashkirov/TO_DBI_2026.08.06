## Детальное описание

### 1.RUBRICATOR_FILES.md
**Назначение**: Список файлов для сканирования  
**Формат**: Markdown с категориями  
**Использует**: GUI приложение для отображения структуры

### 2.RUBRICATOR_CATEGORIES.md
**Назначение**: Категории правил (SQL, Типы_данных, Транзакции и т.д.)  
**Формат**: Markdown с описанием категорий  
**Использует**: GUI приложение для фильтрации

### 3.RUBRICATOR_FIXES.md
**Назначение**: Старый формат правил в Markdown  
**Формат**: Markdown с исправлениями  
**Использует**: Резервный алгоритм, если правило не найдено в JSON

### 4.RUBRICATOR_PROMPTS.json
**Назначение**: Промпты для AI-ассистента KODA  
**Формат**: JSON с regex-паттернами  
**Содержит**:
- `version` — версия формата (2.2.0)
- `rules` — массив правил с:
  - `code` — код правила
  - `short_description` — краткое описание
  - `search_prompt` — инструкция для поиска
  - `fix_prompt` — инструкция для исправления
  - `test_generation_prompt` — инструкция для генерации тестов
  - `regex_patterns.for_search` — паттерны для поиска
  - `regex_patterns.for_ignore` — игнорирующие паттерны
  - `examples` — примеры "было/стало"
  - `fix_instruction` — пошаговая инструкция
  - `priority` — приоритет (high/normal/low)
  - `category` — категория

**Использует**:
- `PLPlusScanner` — сканирование файлов
- `PLPlusFixer` — исправление кода
- `RubricatorPrompts` — модуль работы с рубрикатором

### 5.RUBRICATOR_PARSER_SQL.json
**Назначение**: Гибридный SQL-парсер для автоматических преобразований  
**Формат**: JSON с алгоритмическими правилами  
**Содержит**:
- `version` — версия формата (1.0.0)
- `hybrid_mode` — режим гибридного парсера (true)
- `rules` — массив правил с:
  - `rule_code` — код правила
  - `priority` — приоритет (1/2/3)
  - `patterns` — массив паттернов:
    - `name` — уникальное имя
    - `regex` — регулярное выражение
    - `description` — описание
    - `transform_type` — тип преобразования (regex/hybrid/ignore)
    - `transform` — шаблон замены (для regex)
    - `algorithmic_hint` — подсказка для алгоритмического парсера
    - `fallback_instruction` — инструкция для AI (для hybrid)
    - `example_in` — пример входа
    - `example_out` — пример выхода

**Использует**:
- `sql_parser.py` — алгоритмический парсер (в разработке)

## Гибридный подход

```
┌─────────────────────────────────────────────────────────────┐
│                    Исходный код PLPlus                       │
└────────────────────────┬────────────────────────────────────┘
                         │
            ┌────────────┴────────────┐
            │                         │
            ▼                         ▼
┌──────────────────────┐   ┌──────────────────────┐
│ 4.RUBRICATOR_PROMPTS │   │ 5.RUBRICATOR_PARSER  │
│      (AI KODA)       │   │      (sql_parser)    │
└──────────┬───────────┘   └──────────┬───────────┘
           │                          │
           │  regex_patterns          │  transform_type
           │  for_search              │  = 'regex'
           │  for_ignore              │  → re.sub()
           │                          │
           ▼                          ▼
┌──────────────────────┐   ┌──────────────────────┐
│  Поиск проблем       │   │  Быстрое решение     │
│  через regex         │   │  через regex         │
└──────────┬───────────┘   └──────────┬───────────┘
           │                          │
           ▼                          ▼
┌──────────────────────┐   ┌──────────────────────┐
│  AI анализ           │   │  transform_type      │
│  (если hybrid)       │   │  = 'hybrid'          │
└──────────┬───────────┘   │  → алгоритмический   │
           │               │     парсер           │
           ▼               └──────────┬───────────┘
┌──────────────────────┐              │
│  fallback_instruction│              ▼
│  (если не удалось)   │   ┌──────────────────────┐
└──────────────────────┘   │  transform_type      │
                           │  = 'ignore'          │
                           │  → пропустить        │
                           └──────────────────────┘
```
