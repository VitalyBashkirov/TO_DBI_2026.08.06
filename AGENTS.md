# AGENTS.md - Инструкция для Koda

## Контекст проекта

- **Проект:** АРМ "Адаптация под DBI"
- **Цель:** Автоматическая миграция PL/Plus кода с Oracle на PostgreSQL (DBI).
- **Версия рубрикатора:** 5.3.0
- **Источник правил:** `F:\TO_DBI\DATA\Рубрикатор v5\4.RUBRICATOR_PROMPT v5.json` (332 правила).
- **Активные правила:** v53, тдс20240828, тклоик20240828, PlpCheck.
- **Отказ от старого:** v50, v5.0.0 больше не используются.
- **Koda может и должен использовать инструменты VS Code** (терминал, чтение/запись файлов, открытие документов) для выполнения задач.

## Режим Плана (Plan Mode)

- **Режим по умолчанию:** read-only. Исследуй проект, анализируй, не меняй файлы.
- **Не создавай, не редактируй, не удаляй, не перемещай** файлы.
- **Не запускай** команды, меняющие состояние системы, пакеты, git или сеть.
- **Используй `run_terminal_command` только для чтения** (например, `git status`, `git log`, `dir`).
- **Общайся с пользователем текстом.** Задавай уточняющие вопросы, предлагай варианты.
- **Публикуй план** через `update_plan` только когда он готов к реализации. Каждый шаг должен иметь статус `pending`.
- **Не используй `update_plan` для отслеживания исследования.** Публикуй только шаги реализации и проверки.

## Режим Агента (Agent Mode)

- **Режим реализации:** read-write. Применяй изменения на основе утверждённого плана.
- **Действуй решительно:** используй доступные инструменты (`edit_file`, `run_terminal_command`, `create_new_file`) для реальных изменений.
- **Тестируй код** после написания. Проверяй, что изменения работают.
- **Соблюдай стиль кода** проекта. Делай минимальные изменения для достижения цели.
- **Не запускай `git commit`** и другие git-манипуляции без явной просьбы пользователя.
- **При ошибках:** читай лог/ошибку, исправляй код, перезапускай тесты/команды.

## Инструменты VS Code

- **`read_file` / `ls` / `file_glob_search` / `grep_search`:** Поиск и чтение исходников, конфигов, документации.
- **`run_terminal_command`:** Запуск PowerShell/CMD команд (git, npm, pytest, python, docker и т.д.).
- **`edit_file` / `create_new_file`:** Создание и редактирование кода.
- **`update_plan`:** Управление видимым планом задачи.
- **`fetch_url_content` / `search_web` / `docs_search`:** Внешние данные, документация, веб-поиск (только для специфических запросов).

## Команда DS (файл-задание)

Получив команду `DS <имя файла>`, выполни следующие шаги:

1. **Поиск:** Найди файл в `F:\TO_DBI\EXCHANGE\INBOX`.
2. **Анализ:** Прочитай содержимое. Расценивай файл как **промпт** (задание).
3. **Выполнение:**
   - Если требуется сохранение результата — сохрани его в `F:\TO_DBI\EXCHANGE\OUTBOX` (формат JSON или Markdown).
   - Если действие можно выполнить в VS Code (открыть файл, запустить скрипт, выполнить SQL) — **выполни это через инструменты**.
4. **История:** После успешного выполнения перемести исходный файл из `INBOX` в `F:\TO_DBI\EXCHANGE\PROCESSED`.
5. **Уведомление:**
   - Успех: `-= DS <имя файла> успешно выполнен =-`
   - Ошибка: `-= DS <имя файла> не выполнен =-` + причина.
6. **Логирование:** Запиши ход выполнения в `F:\TO_DBI\EXCHANGE\bot.log`.

### Если файл не указан в команде DS

- Просканируй `F:\TO_DBI\EXCHANGE\INBOX`.
- Обрабатывай файлы последовательно в порядке поступления (по имени или времени создания).
- Если файлов нет, выведи: `-= Нет заданий в INBOX =-`

## Очередь в INBOX и контроль блокировки

- **Последовательность:** Обрабатывай файлы строго по очереди.
- **Проверка блокировки:** Перед чтением файла проверяй, не заблокирован ли он (открыт в редакторе, занят Windows).
- **Если файл заблокирован:**
  - Приостанови обработку этого файла. Жди разблокировки до 10–15 секунд.
  - Если разблокировки не произошло, переходи к следующему файлу в очереди.
  - Заблокированный файл **оставь в INBOX** (не переноси в FAILED).
  - В выводе и логе укажи: `Файл <имя файла> заблокирован (открыт для редактирования).`
- **Ошибки выполнения:** Если промпт выполнен с ошибкой, файл **не удаляй** и **не переноси**. Укажи причину ошибки в выводе и логе.

## Методология исправления PL/Plus

- При нахождении проблемы в PL/Plus коде всегда указывай формат:
  - **Было:** оригинальный код
  - **Стало:** исправленный код
- Используй регулярные выражения из рубрикатора для поиска проблем.
- При необходимости используй AI-анализатор (если он доступен в `scanner.py`).
- Сохраняй структуру каталогов при сохранении результатов, если включён соответствующий флаг.

## Обработка ошибок

- **Не блокируй приложение:** при ошибке логируй причину и переходи к следующему шагу или файлу.
- **Не удаляй рабочие файлы:** если операция не удалась, сохраняй исходники без изменений.
- **Валидируй пути:** перед запуском проверь существование каталогов и файлов.
- **Обработка исключений:** всегда оборачивай внешние вызовы (`subprocess`, `os.startfile`, `ShellExecute`) в `try/except`.
- **Интерфейс:** используй `messagebox` (showinfo, showwarning, showerror) для уведомлений пользователя о критических ошибках.

## Протокол завершения задач (DS_048)

### Автоматизация

**Бот** (`SRC\exchange_bot.py`) **автоматически** переносит файлы из `INBOX` в `PROCESSED` **при условии**:

1. **Ответ Koda** (свежий файл `DS_XXX_*` в `OUTBOX`) содержит **признак** завершения:
   - `-= Задание выполнил =-`
   - `-= DS_XXX успешно выполнен =-`
   - `Задача выполнена`
   - `Проект TO_DBI успешно обработан!`

2. **Иначе** — файл **остаётся** в `INBOX` (Koda **задала** вопрос или **не** завершила).

### Логика финализации

| Состояние ответа | Действие бота | Запись в bot.log |
|---|---|---|
| Маркер завершения | Перенос в `PROCESSED` | `Выполнено. Файл перенесён в PROCESSED.` |
| Маркер ожидания (`Жду вашего решения`, `Что делаем дальше`, `Как поступим`, `Уточните`) | Остаётся в `INBOX` | `Ожидание ответа пользователя. Файл остаётся в INBOX.` |
| Ответ есть, маркеров нет | Остаётся в `INBOX` | `Задача не завершена. Файл остаётся в INBOX.` |
| Ответа нет | Остаётся в `INBOX` (без записи) | — |

### Логирование

Все **события** — в `EXCHANGE\bot.log`.

### Ручное вмешательство

**Если** файл **остался** в `INBOX`:
- **Проверить** `bot.log` — **почему** не перенесён.
- **Если** задача **выполнена** — **перенести** **вручную**.

## Протокол завершения и звукового сигнала

- **Задание выполнено успешно:**
  - Выведи сообщение: `-= Задание выполнено =-`
  - **Проиграй победный звук** через PowerShell:

    ```powershell
    [console]::beep(1000, 300)
    [console]::beep(1200, 300)
    [console]::beep(1500, 500)
    ```

  - Звуковые ноты: 1000 Гц (300мс) → 1200 Гц (300мс) → 1500 Гц (500мс)

- **Задание не выполнено (ошибка):**
  - Выведи сообщение: `-= Задание не выполнено =-` + причина ошибки
  - **Проиграй звук сожаления** через PowerShell:

    ```powershell
    [console]::beep(400, 500)
    [console]::beep(300, 500)
    ```

  - Звуковые ноты: 400 Гц (500мс) → 300 Гц (500мс)

- **Если `[console]::beep` не сработал** (терминал закрыт, системный динамик отключён) — используй **запасной вариант** через системные звуки Windows:
  - Успех (замена победных нот):

    ```powershell
    [System.Media.SystemSounds]::Asterisk.Play()
    ```

  - Ошибка (замена звука сожаления):

    ```powershell
    [System.Media.SystemSounds]::Hand.Play()
    ```

  - Либо проиграй конкретный WAV-файл:

    ```powershell
    $player = New-Object System.Media.SoundPlayer
    $player.SoundLocation = "C:\Windows\Media\chimes.wav"
    $player.Play()
    ```

- **Если звук полностью недоступен** (например, терминал закрыт и системные звуки не работают), выведи текстовую аннотацию:
  - Успех: `(Звук: Победные ноты)`
  - Ошибка: `(Звук: Ноты сожаления)`

## Формат записей в bot.log (DS_050)

### Обязательные требования

1. **Кодировка** — **UTF-8** (без BOM).
2. **Дата/время** — `[ДД.ММ.ГГГГ ЧЧ:ММ:СС]` (с **точкой** между ДД.ММ.ГГГГ).
3. **Формат** — `[ДД.ММ.ГГГГ ЧЧ:ММ:СС] DS XXX: <описание на русском>.`
4. **Кириллица** — **разрешена** и **обязательна**.

### Правильный пример

```
[15.09.2026 16:38:13] DS 049: Выполнено. Протокол завершения Koda. Файл перенесён в PROCESSED.
```

### НЕ использовать

- **Транслит** (`Vypolneno`, `Fail perenesen`, `Protokol zaversheniya`).
- **Смесь** латиницы и кириллицы.
- **Только время** без даты (`[16:38:13]`).
- **Английский язык** (`Task moved to archive`).
- **Слово** `Fail` (ложное).

### Случаи

| Событие | Формат записи |
|---------|---------------|
| **Задача выполнена** | `[ДД.ММ.ГГГГ ЧЧ:ММ:СС] DS XXX: Выполнено. <краткое описание>. Файл перенесён в PROCESSED.` |
| **Задача не завершена** (Koda задала вопрос) | `[ДД.ММ.ГГГГ ЧЧ:ММ:СС] DS XXX: Ожидание ответа пользователя. Файл остаётся в INBOX.` |
| **Ошибка** | `[ДД.ММ.ГГГГ ЧЧ:ММ:СС] DS XXX: Ошибка. <описание>. Файл остаётся в INBOX.` |

### Команда для записи

```powershell
Add-Content -Path "F:\TO_DBI\EXCHANGE\bot.log" -Value "[ДД.ММ.ГГГГ ЧЧ:ММ:СС] DS XXX: <описание>." -Encoding UTF8
```

**ВАЖНО**: параметр `-Encoding UTF8` — **обязателен**.
