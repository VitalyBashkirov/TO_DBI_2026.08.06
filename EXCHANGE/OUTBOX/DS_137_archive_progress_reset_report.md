# DS_137 — Прогресс 100% после архивации результата

## 1. Задача

Чат 29. Основная тема. Прогресс-бар не сбрасывается после архивации
результата (К2 с включённой опцией «Архивировать результат»).

Задача выделена из отложенных чата 28 (см. DS_134, пункт «Прогресс-бар
не сбрасывается после К2»). Оригинальное задание не создавалось —
восстановлено по факту в чате 29, лежит в
EXCHANGE\PROCESSED\DS_137_archive_progress_reset.md.

## 2. Симптом

После К2 с архивацией:
1. Прогресс доходит до 100%.
2. Диалог «Исправление завершено» → ОК.
3. Диалог «Архивация завершена» → ОК.
4. Прогресс-бар остаётся 100%, надпись «100%».

Ожидание: после закрытия диалогов прогресс = 0%, надпись «0%».

## 3. Причина (диагностика чата 29)

Гонка потоков между _run_fix (main thread) и _run_archive (отдельный поток).

_run_fix (L4248-4296):
- L4254-4257: if should_archive → Thread(target=_run_archive).start().
- L4270-4271: after(0, progress.config(0)) + after(0, label("0%")).
- L4273-4279: after(0, _show_copyable_dialog("Исправление завершено", ...)).
- L4287-4296 (finally): after(0, _finish_abortable_operation).

_finish_abortable_operation (L1929-1959):
- L1953: self._reset_progress() → progress.config(0) + label("0%").

_run_archive (L4298-4341):
- L4302: _progress_update(95) → after(0, progress.config(95)).
- L4328: _progress_update(100) → after(0, progress.config(100)).
- L4334: after(0, log("Архив создан")).
- L4335-4337: after(0, _show_copyable_dialog("Архивация завершена", ...)).
- finally отсутствовал.

Порядок событий (фактический):
1. _run_fix запускает _run_archive в отдельном потоке (L4257).
2. _run_fix ставит в очередь after: progress 0 (L4270), диалог «Исправление
   завершено» (L4273), _finish_abortable_operation (L4296).
3. Main thread выполняет _finish_abortable_operation → _reset_progress → 0%.
4. Поток _run_archive ставит after: _progress_update(100) (L4328),
   лог, диалог «Архивация завершена».
5. Main thread выполняет _progress_update(100) → 100%.
6. Прогресс остаётся 100% — никто не сбрасывает.

_run_archive — последний в цепочке, НЕ сбрасывал прогресс. Корень.

## 4. Решение (вариант 3 — двойной сброс)

В _run_archive добавлены два сброса:

1. Явный сброс ПЕРЕД диалогом «Архивация завершена»:
   после _progress_update(100), перед after(0, log("Архив создан")).
   Гарантирует 0% к моменту показа диалога.

2. Гарантированный сброс в finally:
   сработает в т.ч. при исключении. Дубль безопасен (идемпотентно).

Почему не только finally: при успешном сценарии finally выполняется
после возврата из try — сброс попадёт в очередь after ПОСЛЕ диалога
«Архивация завершена». Пользователь увидел бы 100% за диалогом.
Явный сброс перед диалогом решает это.

Почему не только явный сброс: при исключении в try (например, ошибка
zipfile) до явного сброса дело не дойдёт. finally — страховка.
