## Контекст

После тестирования АРМ выявлено: при «Сканировать» с активными флагами DS_053 создаётся только `scan_report_*.md`, а детальный лог `scan_VVxVVx_*.md` — **не создаётся**. При «Исправить код» создаются оба.

**Требуется:** унифицировать поведение — при «Сканировать» создавать **оба** лога, как при «Исправить код», **всегда** (независимо от наличия флагов).

**Каталог `logs\temp\` не используется.** Все логи остаются в `logs\`, как сейчас. Тестовый `logs\temp\DS_053\synthetic.plp` (Тест 1) — не трогаем.

## Требования

### Логи при «Сканировать»

**Всегда** создаются два лога:

1. `F:\TO_DBI\logs\scan_report_<source>_<ts>.md` — табличный отчёт (как сейчас, без изменений).
2. `F:\TO_DBI\logs\scan_VVxVVx_<source>_<ts>.md` — детальный лог.

**Содержимое `scan_VVxVVx_*` при сканировании:**

- **Если активен хотя бы один флаг DS_053:**
  - заголовок (рубрикаторы, флаги, дата, источник);
  - **PLAN** — перечень КР-кодов, которые будут применены;
  - блоки `>` / `<КР>` — **отсутствуют** (фиксов ещё нет);
  - статистика — только по PLAN (сколько правил, разбивка по кодам);
  - `VVxVVx` в имени — по активным флагам (V — выбран, x — не выбран).

- **Если ни один флаг DS_053 не активен:**
  - лог создаётся **пустым**, с пометкой «флаги не выбраны»;
  - `VVxVVx` в имени = `xxxxxx` (все флаги = x);
  - содержимое — заголовок + пометка «флаги не выбраны», без PLAN и без was/became.

### Логи при «Исправить код»

Без изменений (как сейчас):
- `scan_report_*.md` — создаётся;
- `scan_VVxVVx_*.md` — создаётся, с PLAN и блоками `>` / `<КР>` (Схема A из DS_053_Уточнение_2).

## Задачи KODA

### Задача A — `scan_VVxVVx_*` при «Сканировать» (всегда)

В `gui_app.py` / `scanner.py`:

- при «Сканировать» — **всегда** вызывать формирование `scan_VVxVVx_*.md` (тот же метод, что при «Исправить код»);
- если активен хотя бы один флаг — содержимое: заголовок + PLAN, **без** блоков `>` / `<КР>`;
- если ни один флаг не активен — содержимое: заголовок + пометка «флаги не выбраны»;
- путь: `F:\TO_DBI\logs\scan_VVxVVx_<source>_<ts>.md`;
- `scan_report_*.md` продолжает создаваться (не заменяется).

**Критерий:**
- «Сканировать» с флагами → два файла в `logs\`: `scan_report_*` + `scan_VVxVVx_*` с PLAN.
- «Сканировать» без флагов → два файла: `scan_report_*` + `scan_VVxVVx_xxxxxx_*` с пометкой «флаги не выбраны».
- «Исправить код» → два файла, `scan_VVxVVx_*` с PLAN + was/became.

### Задача B — Проверить, что `logs\temp\` не создаётся

**Требуется:**

- убедиться, что `logs\temp\` **не создаётся** ни при старте АРМ, ни при сканировании, ни при исправлении;
- если где-то в коде осталось `os.makedirs("logs/temp")` (например, из DS_053_Уточнение_2, задача B) — убедиться, что оно не срабатывает без необходимости (не удалять, но проверить);
- если `logs\temp\DS_053\` создаётся только для Теста 1 (синтетика) — это допустимо.

**Критерий:** после обычного сканирования / исправления каталог `logs\temp\` не создаётся (или создаётся только при Тесте 1).

### Задача C — Обновить подпись в GUI

В `gui_app.py` заменить текущую подпись над блоком флагов DS_053.

**Было:**

```
Имя лога: scan_VVxVVx (V — флаг выбран, x — нет)
```

**Стало (точный текст, три строки):**

```
Имя дополнительного лога: scan_VVxVVx (V — флаг выбран, x — нет)
Формируется при сканировании и исправлении.
При отсутствии флагов — пустой, с пометкой «флаги не выбраны».
```

**Требования к оформлению:**
- шрифт и цвет — как у прежней подписи (серая, курсив — если так было);
- три строки, выравнивание — по левому краю;
- текст — **точно как выше**, без изменений формулировок.

**Критерий:** в GUI над блоком флагов отображается текст из трёх строк, соответствующий новому поведению.
