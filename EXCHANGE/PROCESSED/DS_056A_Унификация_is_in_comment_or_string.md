## 1. Проблема

Логика «находится ли позиция в комментарии или строковом литерале» **продублирована в трёх местах** с разным качеством:

| Файл | Класс | Сигнатура | Качество |
|------|-------|-----------|----------|
| `SRC\analyzer\scanner.py:489` | `PLPlusScanner` | `(line, match_start, match_end)` | среднее |
| `SRC\fixer\variable_parser.py:330` | `DeterministicFixer` | `(line)` | **слабое** |
| `SRC\fixer\code_fixer.py:990` | `PLPlusFixer` | `(line, match_start, match_end)` | лучшее |

**Подтверждённые баги (DS_056):**
1. `VariableParser` не распознаёт средние строки `/* ... */`.
2. Q-quoting `q'[...]'` — подсчёт кавычек сбивается.
3. Вложенные `/* /* */ */` — счётчик даёт ложное «в комментарии».
4. Многострочный литерал `'...` (без закрытия) — состояние не отслеживается.

## 2. Ключевое архитектурное требование

**`is_in_comment_or_string` НЕ мутирует `state`.**

Обоснование: эта функция вызывается **многократно для одной строки** — по одному разу на каждое regex-совпадение (см. `scanner.py:551`, `code_fixer.py:1114`). Если функция будет мутировать `state` при первом вызове, то при втором вызове в той же строке `state` будет уже сдвинут — и результат окажется **неверным**.

**Решение — разделение ответственности:**

| Метод | Ответственность | Мутирует `state`? | Сколько раз на строку? |
|-------|-----------------|-------------------|------------------------|
| `is_in_comment_or_string(...)` | Только **отвечает на вопрос** для позиции. `state` читает. | **Нет** | Многократно |
| `advance_lexer_state(line, state)` | Обновляет `state` по **всей** строке | **Да** | **Ровно один раз** — после всех `is_...` для этой строки |
| `is_line_fully_in_comment_or_string(line, state)` | Обёртка для VariableParser (строка целиком) | **Нет** | Однократно (по логике VariableParser) |

**Потребители обязаны:**
- вызывать `advance_lexer_state(line, state)` **один раз на строку** — после того, как для неё отработали все вызовы `is_in_comment_or_string`;
- **не** пытаться обновлять `state` вручную вне `advance_lexer_state`.

#	Конструкция	Правило
1	-- ...	До конца строки — комментарий, если не внутри '...' и не внутри /* */.
2	/* ... */	От /* до первого */. Вложенность не поддерживается (Oracle-семантика: первый */ закрывает). Состояние между строками.

4	q'X...X'	X ∈ [ { ( < или любой символ. Внутри q-quoted строки кавычки ' не терминаторы. Регистр q не важен. Все 5 форм.

6	&debug(...)	При debug_mode=True — переменные внутри '...' считаются кодом (сохранить поведение PLPlusFixer).
7	/*+ ... */	Hint. Сохранить текущее поведение PLPlusScanner._is_hint_comment — hint не считается комментарием для целей поиска кода.

9	\r\n (CRLF)	\r не должен ломать определение конца строки. Обрабатывать line.rstrip('\r\n') перед разбором.
