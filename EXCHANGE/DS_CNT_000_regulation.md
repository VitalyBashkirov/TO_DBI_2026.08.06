# Регламент пакетных CLI-задач (DS_CNT)

> DOC_ID: ARM-REG-CNT-000. Версия 1.0. Дата: 2026-10-03.

## 1. Общие положения

1.1. Регламент определяет порядок создания, запуска и контроля пакетных CLI-задач (далее — CNT-задачи) в АРМ «Адаптация под DBI».

1.2. CNT-задачи выполняются вне интерактивной сессии оператора, посредством пакетных скриптов (`.cmd`) и Task Scheduler.

1.3. Ответственный за исполнение CNT-задачи — оператор АРМ (власть учётной записи `DBI\user`). Ответственный за контроль — руководитель проекта.

1.4. Запрещается запуск CNT-задач от имени администратора домена или сервисной учётной записи без согласования с IB.


1.11. **Файловая система F: — NTFS.**
F: — NTFS. Файловые ACL применяются для `svc_mcp`:
- rw: logs, PATCH_OUT;
- ro: DATA, EXCHANGE, PATCH_IN;
- нет доступа: SRC, .git.
svc_mcp — вне групп.
Ограничения MCP-конфига (MCP_SHELL_ALLOW, MCP_GIT_MODE,
MCP_FS_ROOTS_RW/RO) — дополнительно к ACL.


1.12. **CLI Continue.** В публичной версии Continue CLI `ai-continue`
отсутствует. Индексация `@codebase` выполняется вручную в UI Continue
(Settings -> Index). Task Scheduler для этой индексации не применять.
Пакетный режим индексации -- через свой скрипт (DS_CNT_005c).
Проверка MCP-серверов -- в UI Continue (Settings -> MCP).


1.13. **Svoj indeksator.** Dlja paketnogo semanticheskogo poiska
ispolzuetsja sobstvennyj skript 	ools\indexer\ (Ollama +
nomic-embed-text). Indeks - F:\TO_DBI\logs\indexer\. Ne putat'
s Continue @codebase (tam - ruchnaja indeksacija v UI).
Massovyj progone - nochnoj rezhim s rate limiting.


1.14. **Rate limit для Ollama.** Ollama `nomic-embed-text` нестабильна
при массовой нагрузке (>50 запросов подряд — падает/зависает).
При массовой индексации (свой индексатор, DS_CNT_005c) — rate limit
1 req/sec. Нарушение rate limit — риск падения Ollama и срыва ночного
прогона.

1.16. **Ночной pipeline CNT (DS_CNT_007).**
Скрипт: `tools\run_cnt_007_nightly.cmd`.
Состав: инкрементальная переиндексация + /check-standard +
/explain-log + отчёт.
Модель: `qwen2.5-coder:3b` (Ollama, порт 11434). Обоснование:
компромисс между качеством и скоростью на CPU. 1.5b удалена
(устарела, слабое качество); 7b слишком медленна для ночного окна.
Task Scheduler: `TO_DBI_CNT_NightlyPipeline`, 01:00 (по согласованию).
Логи: `logs\ds_cnt_007.log`, `ds_cnt_007.exit`.
Отчёты: `EXCHANGE\OUTBOX\DS_CNT_007_*.md`.
Rate limit 1 req/sec — обязателен.

## 2. Каталог и структура файлов

2.1. Рабочий каталог АРМ: `F:\TO_DBI`.

2.2. Каталоги CNT-задач:

| Каталог | Назначение |
|---------|-----------|
| `F:\TO_DBI\tools\` | Пакетные скрипты `.cmd`, `.ps1` |
| `F:\TO_DBI\logs\` | Логи выполнения, артефакты |
| `F:\TO_DBI\EXCHANGE\OUTBOX\` | Отчёты DS |
| `F:\TO_DBI\EXCHANGE\INBOX\` | Постановки DS |

2.3. Именование скриптов: `run_cnt_<NNN>_nightly.cmd`, где `<NNN>` — порядковый номер задачи.

2.4. Именование логов: `cnt_<NNN>_<YYYYMMDD_HHMMSS>.log`.

2.5. Именование отчётов: `DS_CNT_<NNN>_report.md`.

2.6. Шаблоны скриптов: `_template_nightly.cmd` (не запускать).

## 3. Порядок создания CNT-задачи

3.1. Создать скрипт на основе `_template_nightly.cmd` с уникальным именем по п. 2.3.

3.2. Определить входные данные: файлы, параметры, переменные окружения.

3.3. Реализовать проверку входных данных в начале скрипта. При нехватке — `exit /b 2`.

3.4. Реализовать запись лога в `F:\TO_DBI\logs\` по п. 2.4.

3.5. Заложить `exit /b 0` при успехе, `exit /b 1` при ошибке.

3.6. Локальная проверка: запуск скрипта вручную, контроль кода возврата.

3.7. Зарегистрировать в Task Scheduler (см. раздел 5).

3.8. Создать отчёт `DS_CNT_<NNN>_report.md` в `EXCHANGE\OUTBOX\`.

## 4. Порядок запуска и контроля

4.1. Разрешённые способы запуска:

- Ручной запуск оператором (отладка).
- Task Scheduler (штатный режим).
- Запуск из другого скрипта (цепочка задач).

4.2. Запрещено запускать CNT-задачи из GUI-приложения (Tkinter).

4.3. Коды возврата:

| Код | Значение |
|-----|---------|
| 0 | Успех |
| 1 | Ошибка исполнения |
| 2 | Нехватка входных данных |
| 3 | Ошибка доступа к файлам |
| 4 | Таймаут |

4.4. Контроль:

- Проверить `exit code` после запуска.
- Проверить наличие лога в `logs\`.
- Проверить содержимое лога на `ERROR`, `FATAL`.

4.5. При nonzero exit code — оператор уведомляет руководителя.

## 5. Task Scheduler

5.1. Имя задачи: `DBI_ARM_CNT_<NNN>`.

5.2. Запускать от: оператор АРМ `DBI\user`.

5.3. Условия запуска:

- По расписанию (ночной период 02:00–05:00).
- Только если компьютер бездействует (idle).
- С стопом по таймауту (см. 5.4).

5.4. Таймаут:

- Мягкий: `PT2H` (2 часа) — уведомление.
- Жёсткий: `PT4H` (4 часа) — остановка задачи.

5.5. Разрешить запуск по требованию (AllowStartIfOnBatteries: false).

5.6. Повтор при сбое: не более 2 повторов с интервалом `PT30M`.

## 6. Логирование и артефакты

6.1. Каждый записанный лог содержит:

- Метка времени начала (`START: <timestamp>`).
- Метка времени конца (`END: <timestamp>`).
- Код возврата (`EXIT_CODE: <N>`).
- Сообщения с уровнями `INFO`, `WARN`, `ERROR`.

6.2. Формат строки лога: `[<LEVEL>] <YYYY-MM-DD HH:MM:SS> <message>`.

6.3. Артефакты (результаты) — в `F:\TO_DBI\logs\`. Отчёты — в `F:\TO_DBI\EXCHANGE\OUTBOX\`.

6.4. Ротация логов: хранить последние 30 файлов `cnt_<NNN>_*.log`. Старые — удалять.

6.5. Запрещается писать секреты, пароли, токены в логи.

## 7. Безопасность и ограничения

7.1. Скрипты CNT-задач не должны:

- Использовать внешние сетевые ресурсы (только локальные Ollama/MCP).
- Читать файлы за пределами `F:\TO_DBI`.
- Модифицировать `F:\TO_DBI\DATA\`, `F:\TO_DBI\SRC\`.
- Писать в `F:\TO_DBI\EXCHANGE\INBOX\`.

7.2. Права на скрипты: `DBI\user` — чтение/выполнение; запись — только в `logs\`, `tools\`, `EXCHANGE\OUTBOX\`.

7.3. При использовании MCP: только локальные серверы, учётная запись `DBI\user`, таймаут вызова `PT2M`.

7.4. При использовании `svc_mcp` (сервисная учётная запись MCP):

- Только чтение `F:\TO_DBI\DATA\`.
- Только запись в `F:\TO_DBI\logs\`.
- Запрет: `EXCHANGE\`, `SRC\`, сеть, GUI.
- Пароль: срок действия 90 дней, длина 16 символов.


7.5. Аудит: Task Scheduler ведёт историю запусков (`Get-ScheduledTaskInfo`). Оператор проверяет еженедельно.

7.6. При обнаружении несанкционированного запуска или nonzero exit code в нерабочее время — инцидент в IB.

## 8. Планировщик Windows (Task Scheduler)

### 8.1. Регистрация задачи

```cmd
schtasks /Create /TN "TO_DBI_CNT_NightlyPipeline" /TR "<path>\run_pipeline.cmd" /SC DAILY /ST 01:00 /F
```

### 8.2. Известные ограничения

| Проблема | Причина | Решение |
|----------|---------|---------|
| STATUS_CONTROL_C_EXIT | `timeout /t 1` не работает в сессии 0 | Заменить на `ping -n 2 127.0.0.1 > nul` |
| Ollama недоступен | Модель не загружается в неинтерактивной сессии | "Run only when user is logged on" |
| Прерывание по таймауту | Дефолтный таймаут Планировщика | Увеличить время ожидания |

### 8.3. Рекомендация

Для pipeline с Ollama использовать:
- **Вариант A:** Планировщик + "Run only when user is logged on".
- **Вариант B:** Скрипт-обёртка с логированием и повтором при ошибке.
- **Вариант C:** Запуск через `schtasks /Run` вручную.

### 8.4. Мониторинг

```cmd
schtasks /Query /TN "TO_DBI_CNT_NightlyPipeline" /V /FO LIST
```

Поля: `Last Run Time`, `Last Result` (0 = успех), `Status`.
