## НОВЫЕ ПРАВИЛА / УРОКИ ЧАТА 39

### §6.6.34 — PS-строки с Python-кодом (критично)

1. \n в PS-одинарной строке '...' → в Python-файл \n (перевод строки) — правильно.
   \\n в PS-одинарной строке → в Python-файл \\n (литерал) — ошибка (ast.parse не ловит, если внутри #).
2. \' в PS-одинарной строке — не экранирование. Использовать chr(39) или chr(95) для _.
3. Start-Transcript — только абсолютный путь от F:\TO_DBI + -ErrorAction Stop.
4. Очистка PS\ в начале каждого блока. Исключение — файлы, открытые pytest (-notlike 'pytest_*'), удалять отдельным блоком.
5. Start-Process + RedirectStandardOutput + WaitForExit(ms) — для долгих команд (pytest). Tee-Object — буферизует до завершения → кажется, что висим.
6. $p.ExitCode после WaitForExit — может быть $null в PS 5.1. Фикс: $p.Refresh() или $p.HasExited.
7. Start-Process ollama serve (не ollama serve в текущей сессии). ollama list не вызывать (зависает на Windows). Использовать Invoke-WebRequest /api/tags.
8. Python inline с $ в строке — только через here-string + .py (не python -c).
9. repr() кириллицы в Tee-Object — портится (cp1251). Использовать $env:PYTHONIOENCODING = 'utf-8'.

### §6.6.35 — Семантика значков дерева правил

- ✓ — все правила выбраны (all_on).
- ◐ — хотя бы одно, но не все (enabled).
- ✗ — ни одного (not enabled).

Значок рубрикатора не зависит от var (selected_rules[file_code]) — только от состояния правил. var остаётся True при «Сбросить все» (вариант B), но значок ✗.

### §6.6.36 — _populating_tree — защита от рекурсии

При _populate_rules_tree устанавливается _populating_tree = True. _sync_plpcheck_checkbox проверяет флаг и выходит — иначе trace plpcheck_enabled_var → все 152 правила PlpCheck. Флаг снимается в конце _populate_rules_tree.
