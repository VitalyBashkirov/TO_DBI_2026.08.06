PLAN:
LINE AUTO ДЕЙСТВИЕ

text

**Требования:**

- Колонка `LINE` — **первая**, как в `scan_report_*`.
- Действия с одинаковым `LINE` — рядом (сортировка по `LINE`).
- Внутри одного `LINE` — порядок как в `scan_report_*` (по `№`).
- Ширина колонок — по контенту.

## 4. Формат «Прогноз» (новый)

### 4.1. Пример (МКР = 33)
Прогноз:

Строка 10:
..................................> dp integer:=0; --управление debug_pipe
<plpcheck.BAD_PREFIX > v_iDp integer:=0; --управление debug_pipe

Строка 14:
..................................> fmt24 string(22):='dd/mm/yyyy HH24:MI:SS';
<plpcheck.NOT_MENTIONED > (удалить строку)

Строка 31:
..................................> P_PARAM ref [REPS_PARAMS]; -- ссылка на реализацию филиала
<plpcheck.PREFIX_TYPE_IN_VAR_NAME > v_rParam ref [REPS_PARAMS]; -- ссылка на реализацию филиала

Строка 58:
..................................> P_PARAM := [str].get_str_par(P_ADDS, 'P_PARAM');
<plpcheck.WRONG_METHOD_SYNTAX > P_PARAM := ::[str].get_str_par;

text

### 4.2. Формулы

| # | Формула |
|---|---------|
| 1 | **МКР** = `max(len(код_правила))` **без** `<` и `>` + 1 |
| 2 | **Строка 1:** `[МКР точек]>[пробел]<исходный текст>` |
| 3 | **Строка N:** `<[код][МКР − 1 − len(код) пробелов]>[пробел]<итоговый текст>` |

**Проверка длины префикса:**
- Строка 1: `МКР + 1` символов (МКР точек + `>`).
- Строка N: `1 + len(код) + (МКР − 1 − len(код)) + 1 = МКР + 1`. ✅

### 4.3. Правила

| # | Правило |
|---|---------|
| 1 | `LINE` — заголовок блока |
| 2 | Группировка по `LINE`: одна строка = один блок |
| 3 | Цепочка правил внутри блока (по порядку из `scan_report_*`) |
| 4 | Цепочка **обрывается** при `(удалить строку)` / `(удалить диапазон)` |
| 5 | Полный текст строки (без обрезки) |
| 6 | Пустая строка между блоками |
| 7 | Формат кода: `<plpcheck.NAME>` — без закрывающего `>` |
| 8 | Заглушка AI: `[AI] Требуется AI-анализ: <не реализовано>` |
| 9 | **В конце «Прогноза»** — «Статистика по файлу» + итоговая статистика |

### 4.4. Коды правил — формат B

Используется **полный** код с префиксом `plpcheck.` (как сейчас в `scan_V`):

| Краткий (scan_report) | Полный (scan_V) |
|-----------------------|-----------------|
| `bad_prefix` | `plpcheck.BAD_PREFIX` |
| `not_mentioned` | `plpcheck.NOT_MENTIONED` |
| `prefix_type_in_var_name` | `plpcheck.PREFIX_TYPE_IN_VAR_NAME` |
| `wrong_method_syntax` | `plpcheck.WRONG_METHOD_SYNTAX` |
| `code_in_comment` | `plpcheck.CODE_IN_COMMENT` |

### 4.5. Итоговая статистика

**После блоков «Прогноз»** — два блока:
Статистика по файлу:
plpcheck.BAD_PREFIX: 10
plpcheck.NOT_MENTIONED: 6
plpcheck.PREFIX_TYPE_IN_VAR_NAME: 5
plpcheck.CODE_IN_COMMENT: 4
plpcheck.WRONG_METHOD_SYNTAX: 1

Всего проблем: 26
Всего файлов: 1

text

**Требования:**

- «Статистика по файлу» — **все** коды, сработавшие в файле.
- Сортировка — по **убыванию** количества; при равенстве — по алфавиту.
- `Всего проблем: N` = сумма количеств по всем кодам (= число issues в `scan_report_*`).
- `Всего файлов: M` — число файлов в текущем сканировании.
