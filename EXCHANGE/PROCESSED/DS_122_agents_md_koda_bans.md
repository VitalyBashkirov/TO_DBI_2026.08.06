## Контекст

Чат 19 выявил 4 случая подряд, когда KODA выполняла не то,
что написано в DS, а то, что подсказывает **имя файла**:

| Задание | Что сделала KODA |
|---------|------------------|
| DS_118 | Подмешала правила DS_052 |
| DS_118-fix | Подмешала правила DS_053 |
| DS_118-fix2 | Выполнила параллельный DS_082b |
| DS_118-fix3 | Создала новый файл вместо перезаписи |

**Причина:** KODA ориентируется на имя INBOX-файла, а не на содержимое.

## Задача

Добавить в `F:\TO_DBI\AGENTS.md` новый подраздел
**«### Запрещено при выполнении DS (DS_122)»** внутри раздела
**«## Работа с DS-заданиями»**, **непосредственно перед** существующим
подразделом **«### Что не делать»**.

## Что вставлено

```markdown
### Запрещено при выполнении DS (DS_122)

Ниже — жёсткие запреты. Нарушение = DS не выполнен.

1. **Не создавать новый файл в OUTBOX** вместо перезаписи существующего.
   Если в DS сказано «ПЕРЕЗАПИСАТЬ файл X» — перезаписать именно X.
   Не создавать X_new.md, X_v2.md, X_fixed.md.

2. **Не менять имя задания.**
   Имя INBOX-файла = имя PROCESSED-файла.
   fix2 → fix3 — запрещено; fix3 → fix2 — запрещено.

3. **Не писать в `EXCHANGE\bot.log` произвольные строки.**
   Только те, что явно указаны в INBOX-файле.
   Никаких «DS 082b», если задание — не DS 082b.

4. **Не игнорировать пронумерованные шаги DS.**
   Шаги 1, 2, 3... — обязательные, не рекомендации.
   Шаг «НАЙТИ файл X» — обязателен. Шаг «ПЕРЕЗАПИСАТЬ» — обязателен.

5. **Не подмешивать правила параллельных DS.**
   Каждый DS автономен. Если в INBOX лежат два файла —
   выполнять только тот, что указан в текущей команде DS.

6. **При обнаружении конфликта** — остановиться, доложить
   в `EXCHANGE\OUTBOX\` отчётом с явной формулировкой проблемы.
   Не «додумывать» задание.
```
