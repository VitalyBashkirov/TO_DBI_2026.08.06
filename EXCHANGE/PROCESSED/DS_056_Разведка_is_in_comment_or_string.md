### Шаг 4. Сформулировать проблемные кейсы

На основе шагов 1–3 составить список **конкретных кейсов**, где текущая `_is_in_comment_or_string` может ошибаться. Минимум:
- многострочный комментарий `/* ... */`, внутри которого есть `--`, `'`, `"`.
- многострочный комментарий, разрывающий строку с `&debug(...)`.
- `&debug(...)` в:
  - обычном коде,
  - внутри `--` комментария,
  - внутри `/* */`,
  - внутри строкового литерала.
- `q'[...]'`, `q'{...}'`, `q'(...)'`, `q'<...>'` (если применимо).
- экранирование `''` внутри строки.
- `--` в конце строки без перевода строки (EOF).
- вложенные `/* /* */ */` (ожидаемое поведение — по документации; в Oracle формально не поддерживается, но нужно знать, как трактует CFT).

Для каждого кейса: **ожидаемое поведение** (по документации) vs **предполагаемое текущее** (по коду).
