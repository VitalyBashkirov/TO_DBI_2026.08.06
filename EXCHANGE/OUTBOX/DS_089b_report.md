## 5.8. Расхождения / стоп

1. **Resume = следующий запуск, а не живой поток.** §2.3/§2.4 пишут «при
   Продолжить — проверить _abort_state». В текущей архитектуре к моменту
   второго клика поток уже завершился (graceful stop делает break), поэтому
   фильтр применяется при следующем запуске «Сканировать»/«Исправить».
   Второй клик («Продолжить») лишь логирует наличие состояния. Функции
   `_resume_scan`/`_resume_fix` как отдельные методы не создавались — их
   логика встроена в `_run_scan`/`_run_fix` (меньше вторжений, тот же эффект;
   тестируемые методы `_ds089b_*` вынесены отдельно).
2. `_abort_state` в `on_abort_click` не заполняется (см. 5.2) — заполняется в
   конце операции, где обработанные ключи/файлы точно известны.
3. Файлы `send_to_ai`/`receive_from_ai`/`ai_local_worker`, `scanner.py`,
   `tools\`, layout — не изменялись (§4). `code_fixer.py` — только resume.
4. GIT — не коммитил (по §4 задачи).
5. Побочный артефакт: пустой каталог `SRC\tests\OUTBOX\` (не создан этой
   задачей) — не трогал.
