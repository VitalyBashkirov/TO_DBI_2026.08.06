## 1. Цель

Уточнить логику обработки issues **внутри одной строки** в блоке «Прогноз» `scan_VVxVVx_*` (`save_scan_only_log`, `SRC\fixer\code_fixer.py`).

**Проблема:** в DS_067 §4.3 п.4 сказано «цепочка обрывается при `(удалить строку)` / `(удалить диапазон)`». Формулировка **пассивная** — не задаёт порядок. На практике `NOT_MENTIONED` (удаление) выводится **последним** — после переименований, что **бессмысленно**.

## 3. Уточнённые правила

### 3.1. Приоритет удаления (главное уточнение)

**Проверка на удаление — приоритет 1.**

1. Перед построением цепочки issues для строки — проверить: есть ли среди issues хотя бы одна с действием **удаления** (`(удалить строку)` / `(удалить диапазон)` / `(удалить объявление)`).
2. Если **есть** → вывести **только её** (одна строка цепочки). Остальные issues строки **не выводить**.
3. Если **нет** → строить цепочку из всех issues в порядке `scan_report_*` (по `№`).

**Обоснование:** если строка удаляется, переименования в ней **не имеют смысла**.

### 3.2. Порядок issues в цепочке

**По `№` из `scan_report_*`.** Если на одной строке несколько issues — порядок **строго** как в `scan_report_*` (по возрастанию `№`).

### 3.3. PLAN — порядок внутри `LINE`

**По `№` из `scan_report_*`.** Если на одной строке несколько issues — порядок **строго** как в `scan_report_*` (по возрастанию `№`).

### 3.4. `not_mentioned` → `(удалить объявление)`

Действие `not_mentioned` (правило «Удалить объявление») — итоговый текст **`(удалить объявление)`**, а не `(удалить строку)`.

**Исключение:** `code_in_comment` — итоговый текст **`(удалить строку)`**.

## 4. Пример

### 4.1. Строка 14 — приоритет удаления

**Было (DS_067):**
Строка 14:
.................................> fmt24 string(22):='dd/mm/yyyy HH24:MI:SS';
<plpcheck.BAD_PREFIX > v_sFmt24 string(22):='dd/mm/yyyy HH24:MI:SS';
<plpcheck.NOT_MENTIONED > (удалить строку)

text

**Стало (DS_067_Уточнение_A):**
Строка 14:
.................................> fmt24 string(22):='dd/mm/yyyy HH24:MI:SS';
<plpcheck.NOT_MENTIONED > (удалить объявление)

text

### 4.2. Строка 17 — цепочка без удаления
Строка 17:
.................................> function iif(v1 boolean, v2 varchar2(32767), v3 varchar2(32767)) return varchar2(32767) is
<plpcheck.NOT_MENTIONED > (удалить объявление)

text

**Обоснование:** `not_mentioned` (удаление) — приоритет 1, цепочка обрывается на первой строке.

### 4.3. PLAN — порядок по `№`

**Было (DS_067):**
14 [ignore] > Переименовать в "v_sFmt24"
14 [ignore] > Удалить объявление

text

**Стало (DS_067_Уточнение_A):**
14 [ignore] > Удалить объявление
14 [ignore] > Переименовать в "v_sFmt24"

text
