# DS_133 — Активация кнопок 1/2/3/4 по артефактам на диске

**Дата:** 2026-10-09
**Ветка:** feature/dockerization
**Автор DS:** DeepSeek
**Чат:** 27

## Задача

Кнопки главной панели АРМ «Адаптация под DBI» должны активироваться
в зависимости от артефактов на диске — так, чтобы состояние сохранялось
после перезагрузки компьютера в любой момент.

## Отменён DS_087 §2.3

Старая модель «workflow 1→2→3, ровно одна активна, жирный шрифт» отменена.
Причина: она опиралась на `scan_results` в памяти (`scan_done`, `fix_done`),
который теряется при перезагрузке. Новая модель опирается на артефакты на диске.

## Новая модель активации

| Кнопка | Подпись | Условие `normal` |
|--------|---------|------------------|
| К1 | «1. Сканировать» | `source` существует + R_OK, `pattern` непустой, `any_rule` |
| К2 | «2. Исправить код» | `result` существует + W_OK, `_result_dir_has_pattern_files()` |
| К3 | «3. В Ai» | `result` существует + W_OK, есть `*.plp`, `AI_IN` пуст |
| К4 | «4. Из Ai» | `AI_OUT` содержит `AI_RESPONSE_*.md/json` |

**Жирный шрифт** (`WorkflowActive.TButton`) = кнопка доступна;
**тонкий** (`WorkflowNormal.TButton`) = недоступна.

**Единственный источник правды** — артефакты на диске:
- `*.plp` в каталоге результатов,
- `AI_REQUEST_*.md` в `EXCHANGE\AI_IN`,
- `AI_RESPONSE_*.md/json` в `EXCHANGE\AI_OUT`.

## Восстановление после перезагрузки

| Что было прервано | К1 | К2 | К3 | К4 |
|-------------------|----|----|----|----|
| Ничего | по условиям | по `*.plp` | по `AI_IN` | по `AI_OUT` |
| Скан (часть `*.plp` записана) | ✅ | ✅ (если `*.plp` есть) | ✅ (если `AI_IN` пуст) | ❌ |
| Фикс (часть `*.plp` записана) | ✅ | ✅ | ✅ | ❌ |
| AI-отправка (`AI_REQUEST` создан) | ✅ | ✅ | ❌ (запрос есть) | ❌ |
| AI-ответ получен (`AI_RESPONSE`) | ✅ | ✅ | ✅ (если `AI_REQUEST` архивирован) | ✅ |
| AI-ответ применён | ✅ | ✅ | ✅ | ❌ |

Состояние восстанавливается **автоматически** — при загрузке формы
и при любом изменении переменных (`trace_add` уже настроены).
