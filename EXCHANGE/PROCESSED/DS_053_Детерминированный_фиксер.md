## Контекст

**Проблема:** `PLPlusFixer.fix_file()` (строки 1229–1260) **игнорирует параметр `issues`** — список проблем от сканера. В пайплайне вызывается только `DeterministicFixer` (переименование переменных + удаление неиспользуемых). Детерминированные SQL-правила не применяются:

- `SRC\analyzer\sql_parser.py` — **готовый** модуль для работы с `5.RUBRICATOR_PARSER_SQL v5.json` (методы `apply_fix`, `fix_line_with_fallback`, `process_line`).
- `SRC\fixer\code_fixer.py` — **импортирует** `apply_fix as sql_apply_fix` (строка 16), но **не вызывает** его в `fix_file()`.
- `self.FIXES = self._get_default_fixes()` — резервные regex-правила (строка 446), тоже не применяются в потоке.

**Итог:** SQL-проблемы (ROWNUM, DATE, DECODE, (+), SYSDATE, CONNECT BY, WHENTHERS и др.) сканер находит, но фиксер **не исправляет**.

**Верификация отсутствует:** после фикса нет повторного сканирования — неизвестно, исчезли ли проблемы. `fix_file` возвращает `True` только по факту переименования переменных.

## Требования

### 1. Единый детерминированный конвейер

Реализовать полный конвейер в `PLPlusFixer.fix_file()`:

```
Читать файл → lines[]

Для каждого issue из scanner:
  a. sql_parser.apply_fix(line, rule_code)   ← regex + hybrid
  b. Если не сработал → self.FIXES[rule_code] ← backup regex
  c. Зафиксировать change: {line, before, after, rule_code}

DeterministicFixer (переменные) ← как сейчас

Верификация: повторный скан → fixed / needs_manual

Статистика по ВСЕМ rule_code

Лог scan_VVxVVx_*.md
```

**Порядок:** `sql_parser.apply_fix (regex + hybrid)` → `DeterministicFixer` → `FIXES` (backup).

**Важно:** `issues` от сканера используется как вход. Сканер и фиксер работают с **одним и тем же механизмом поиска** (единый RuleEngine).

### 2. Флаги замены в GUI

Добавить 6 чекбоксов на главную форму:

| Флаг | Смысл |
|------|-------|
| **regex** | Детерминированные (`transform_type: "regex"`) |
| **hybrid** | Полудетерминированные (`transform_type: "hybrid"` с `algorithmic_hint`) |
| **AI-fallback** | AI-fallback (в DS_053 — только пометка, вызов AI отложен в DS_054) |
| **ignore** | Не подлежат автофиксу (только уведомление) |
| **backup regex rules** | Резервные правила из `self.FIXES` |
| **other** | `hybrid` без `algorithmic_hint` |

**Логика:** АРМ ищет и выполняет только те правила, которые выбрал пользователь.

**Единый механизм:** функционал поиска и замены **один** — и для «Сканировать», и для «Исправить код».

### 3. Формат имени лога

При установке хотя бы одного флага — формировать дополнительный лог в каталоге `F:\TO_DBI\logs`:

```
F:\TO_DBI\logs\scan_VVxVx_patch_REPS_EXP_115_1_20260916_152316.md
```

**Формат `VVxVx`:**

| Позиция | Флаг | V | x |
|---------|------|---|---|
| 1 | regex | выбран | не выбран |
| 2 | hybrid | выбран | не выбран |
| 3 | AI-fallback | выбран | не выбран |
| 4 | ignore | выбран | не выбран |
| 5 | backup regex rules | выбран | не выбран |
| 6 | other | выбран | не выбран |

**Пример:** `scan_VVxVVx_...` — включены regex, hybrid, ignore, backup; выключены AI-fallback, other.

### 4. Содержимое лога `scan_VVxVVx_*.md`

**Заголовок:**

```
Отчёт сканирования: scan_VVxVVx_<source>_<timestamp>.md
Активные рубрикаторы и флаги:
  Рубрикаторы: <список>

  Флаги замены:
    regex: V
    hybrid: V
    AI-fallback: x
    ignore: V
    backup regex rules: V
    other: x
```

**По каждому файлу:**

- **PLAN** (первое описание) — КР-коды (коды правил) для замены:

```
PLAN: v53.SQL.ROWNUM.п.1.2, v53.SQL.DECODE.п.1.6.1, PlpCheck.STYLE.BAD_PREFIX.п.4.3
```

- **Строки лога:**
  - Строки «Было» с префиксом `>`.
  - Строки «Стало» с префиксом `<КР>` (где КР — код правила).
  - Если в строке исходного кода несколько разных правил — формировать несколько строк лога для каждого типа правила.
  - Правила к одной строке применяются **в порядке их появления в `issues`** (в порядке обнаружения сканером). Каждое следующее правило применяется к текущему (уже изменённому) состоянию строки.
  - «Стало» может быть несколько.

**Пример:**

```
Строка 42:
  was: where rownum = 1
  <v53.SQL.ROWNUM.п.1.2> became: where FETCH FIRST 1 ROWS ONLY

Строка 68:
  was: nvl(a, b)
  <v53.SQL.DECODE.п.1.6.1> became: CASE WHEN a IS NULL THEN b ELSE a END
  <backup.FIXES.001> became: <дополнительное преобразование>
```

- **Статистика по файлу** (в конце):

```
Статистика по файлу:
  v53.SQL.ROWNUM.п.1.2: 3
  v53.SQL.DECODE.п.1.6.1: 1
  PlpCheck.STYLE.BAD_PREFIX.п.4.3: 2
  backup.FIXES.001: 2
  needs_ai_fix: 1
  needs_manual: 0
```

- **Сводная статистика** (если файлов > 1):

```
Сводная статистика:
  Всего файлов: N
  Всего исправлений: M
  Топ-5 правил: ...
```

### 5. Верификация

После применения фиксов к файлу — **повторный прогон `PLPlusScanner`** по исправленному тексту.

- **Устранённые проблемы** → `fixed`.
- **Оставшиеся** → `needs_manual` (или `needs_ai_fix`, если флаг AI-fallback выбран).
- **Никогда не помечать проблему как исправленную, если она осталась.**
