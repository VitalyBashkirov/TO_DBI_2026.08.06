## Вывод в PS и логи — правила чата 34

### Принципы

1. Строки типа Лог: <путь> — зелёным: Write-Host "Лог: $log" -ForegroundColor Green.
2. Ошибки — красным: Write-Host "FAILED" -ForegroundColor Red.
3. Заголовки секций — Cyan: Write-Host "=== ... ===" -ForegroundColor Cyan.
4. Итоговый статус (OK) — зелёным: Write-Host "OK" -ForegroundColor Green.
5. Данные (таблицы, git diff) — через | Out-Host (не | Format-Table без пайпа).
6. Кириллица в Python-print через cp866-консоль — кракозябры (§6.6.21),
   данные в файле корректны, не влияет на результат.

### Типовой шаблон блока

~~~powershell
# ============================================================
# N1. <Название блока>
# Дата: YYYY-MM-DD
# Назначение: <что делаем>
# Ожидание: <что должно быть>
# Риски: <что может пойти не так>
# ============================================================

$ErrorActionPreference = 'Continue'
$proj = 'F:\TO_DBI'
Set-Location $proj

# N7 v7: очистка PS\ (сохраняя persist\)
if (Test-Path "$proj\PS") {
    Get-ChildItem "$proj\PS" -Exclude 'persist' -ErrorAction SilentlyContinue |
        Remove-Item -Recurse -Force -ErrorAction SilentlyContinue
} else {
    New-Item -ItemType Directory -Path "$proj\PS" | Out-Null
}
if (-not (Test-Path "$proj\PS\persist")) {
    New-Item -ItemType Directory -Path "$proj\PS\persist" | Out-Null
}

$log = "$proj\PS\<имя_блока>.log"
Start-Transcript -Path $log -Force | Out-Null

# ... работа ...

Write-Host "`n=== Секция ===" -ForegroundColor Cyan
<команда> 2>&1 | Out-Host

Write-Host "`nOK" -ForegroundColor Green
Write-Host "Лог: $log" -ForegroundColor Green

Stop-Transcript | Out-Null
~~~

### Что НЕ делать

- Не использовать return в ручных блоках (правило №19), кроме fail-fast
  в if-ветке ошибки (§6.6.3).
- Не полагаться на $LASTEXITCODE после Select-String (правило №22).
- Не читать .log через Get-Content в PS 5.1 (§6.6.15) — только через Python
  с encoding='utf-8'.
- Не использовать -like для подстроки (§6.6.9) — использовать .Contains().
- Не использовать Add-Content -Encoding UTF8 в PS 5.1 (§6.6.20) — только
  [System.IO.File]::AppendAllText с UTF8Encoding($false).

### Кодировки

- .py / .md / .json / .ini / .sql — UTF-8 БЕЗ BOM (§6.1).
- .ps1 с кириллицей — UTF-8 С BOM.
- Все файлы через [System.IO.File]::WriteAllText или AppendAllText
  с UTF8Encoding($false).

## DS_145 — deep_scanner.py — фильтр временных (разъяснение)

### Что такое deep_scanner.py

SRC\analyzer\deep_scanner.py — модуль углублённого сканирования
PL/SQL-кода. Используется в K1 (_run_scan(deep_mode=True)) — вызывается
из АРМ при включённой галке «Углублённое сканирование» (или по кнопке).

В отличие от обычного scanner.py, deep_scanner:
- Обходит все подкаталоги ИК (рекурсивно).
- Анализирует PL/SQL AST (не просто регулярки).
- Ищет сложные паттерны (контекстные зависимости, цепочки вызовов).

### Проблема: временные файлы

В ИК бывают временные / служебные файлы:
- *.plp~ — резервные копии редакторов.
- *.plp.bak, *.bak — бэкапы.
- *.tmp, *.temp — временные.
- ~$*.plp — lock-файлы MS Office.
- .DS_Store, Thumbs.db — мусор ОС.
- Файлы в каталогах .git/, __pycache__/, node_modules/.
- Файлы с временными метками в имени (file_20260101_120000.plp).
- Файлы с расширениями .swp, .swo (Vim).

Что происходит сейчас: deep_scanner обрабатывает такие файлы —
тратит время, выдаёт ложные issues, замусоривает отчёты.
