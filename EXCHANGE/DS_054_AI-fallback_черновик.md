## Контекст

В DS_053 AI-fallback был реализован как **пометка** `needs_ai_fix` — без реального вызова AI. В DS_054 реализуется **файловый обмен** с AI:

- KODA формирует файл-запрос с проблемами;
- пользователь отправляет его в AI (DeepSeek, llama-cpp-python, KODA, человек — АРМ не знает, какой именно);
- AI возвращает файл-ответ;
- KODA обрабатывает ответ: применяет исправления, обновляет логи, пишет в КР.

**АРМ не вызывает AI напрямую.** Всё общение — через файлы в `EXCHANGE\`.

## Каталоги

Создать (или использовать существующие):

```
F:\TO_DBI\EXCHANGE\AI_IN
F:\TO_DBI\EXCHANGE\AI_OUT
F:\TO_DBI\EXCHANGE\AI_IN_PROCESSED
F:\TO_DBI\EXCHANGE\AI_OUT_PROCESSED
```

**Назначение:**

| Каталог | Что там |
|---------|---------|
| `AI_IN` | Файлы-запросы для AI (сформированы KODA, ждут отправки) |
| `AI_OUT` | Файлы-ответы от AI (положены пользователем/скриптом, ждут обработки) |
| `AI_IN_PROCESSED` | Обработанные файлы-запросы (архив) |
| `AI_OUT_PROCESSED` | Обработанные файлы-ответы (архив) |

## Вопрос к AI

Для каждой проблемы предложи исправление. Ответ оформи как JSON-массив:

```json
[
  {
    "id": <номер>,
    "line": <номер>,
    "before": "<исходный код строки>",
    "after": "<исправленный код или null>",
    "reason": "<обоснование, 1-2 предложения>",
    "confidence": <0.0-1.0>
  }
]
```

**Требования:**
- Роль: эксперт по миграции PL/SQL → PostgreSQL (DBI) и стандартам ЦФТ.
- Не меняй ничего, кроме указанной строки.
- Сохраняй отступы и комментарии.
- Если предлагаешь удалить строку — `after = "-- (удалено)"`.
- Если не уверен — `confidence < 0.5` и добавь "needs_manual" в reason.
