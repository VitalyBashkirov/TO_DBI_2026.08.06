## 1. Что за проект

**АРМ «Адаптация под DBI»** — настольный инструмент (Python/Tkinter) для автоматической
миграции PL/Plus кода с Oracle-синтаксиса на архитектуру DBI (PostgreSQL).

Схема работы: **АРМ сканирует код → находит проблемы по рубрикатору → генерирует отчёты
(Markdown/HTML) → код-фиксер применяет исправления → результат в PATCH_OUT**.

## 3. Протокол DS (файловый обмен)

Каталоги: `F:\TO_DBI\EXCHANGE\{INBOX, OUTBOX, PROCESSED}` + лог `bot.log`.

Команда `DS [файл]`:
1. Взять файл из `INBOX` (по очереди; если файл заблокирован — ждать 10–15 сек, потом пропустить, **оставить в INBOX**).
2. Файл = промпт-задание. Выполнить.
3. Результат → `OUTBOX` (JSON или Markdown, как требует задание).
4. При успехе переместить задание в `PROCESSED`. При ошибке — **не удалять, не переносить**, указать причину.
5. Записать ход в `bot.log` (кодировка **cp1251**, формат `[ДД.ММ.ГГГГ ЧЧ:ММ:СС] Сообщение`).
6. Вывести: `-= DS <файл> успешно выполнен =-` или `-= DS <файл> не выполнен =-` + причина.

Формат JSON-результата: `{status, task, file, issues[{issue_type, line_number, description, original_code, fixed_code}], fixes[...]}`.

## 4. Правила оформления и кодировки

- Исходники/документация: **UTF-8**; логи: **cp1251**; файлы OUTBOX: переводы строк **CRLF**.
- Проблемы в PL/Plus оформлять: **Было:** `<код>` → **Стало:** `<код>`.
- Звук при завершении: успех — `[console]::beep(1000,300); (1200,300); (1500,500)`, ошибка — `(400,500); (300,500)`.
- Git-коммиты — **только по явной просьбе пользователя**.
- Символы `>>>` / `<<<` в задании означают пример текста журнала/логов АРМ.
