## НОВЫЕ ПРАВИЛА / УРОКИ ЧАТА 40

### §6.6.34 — PS-строки с Python-кодом (критично)

1. \n в PS-одинарной строке '...' → в Python-файл \n (перевод строки) — правильно.
   \\n → литерал \\n — ошибка (ast.parse не ловит, если внутри #).
2. \' в PS-одинарной строке — не экранирование. Использовать chr(39) или chr(95) для _.
3. Start-Transcript — только абсолютный путь от F:\TO_DBI + -ErrorAction Stop.
4. Очистка PS\ в начале каждого блока. Исключение — файлы, открытые pytest (-notlike 'pytest_*'), удалять отдельным блоком.
5. Start-Process + RedirectStandardOutput + WaitForExit(ms) — для долгих команд. Tee-Object буферизует до завершения → кажется, что висим.
6. $p.ExitCode после WaitForExit — может быть $null в PS 5.1.
   6a-v2: WaitForExit() + Start-Sleep -Milliseconds 50 + $p.Refresh() + fallback по stdout (\d+ passed без failed).
7. Start-Process ollama serve (не ollama serve в текущей сессии). ollama list не вызывать (зависает). Использовать Invoke-WebRequest /api/tags.
8. Python inline с $ — только через here-string + .py (не python -c).
9. repr() кириллицы в Tee-Object — портится (cp1251). Использовать $env:PYTHONIOENCODING = 'utf-8'.
10. 6b: python $pyPath без | Out-Host не попадает в Start-Transcript.
11. 6c: очистка PS\ — в try/finally, до любого return.
12. 6d: indent == ' ' * N хрупкая → indent != '' and '\t' not in indent.
13. 6e: якорь в нескольких местах → искать внутри области метода (def X → m_start, поиск после).
14. 6f: src.replace(old, new, 1) в here-string хрупок → splitlines + поиск по префиксу def .
15. 6g: в PS\ не оставлять .out, .err, .tmp, .bin, .dat. Разрешены .log, .txt, .md, .json, .ini, .py, .ps1, .csv, .sql, *.bak_*. pytest stdout/stderr → PS\pytest_*.log.

### §6.6.35 — Семантика значков дерева правил

- ✓ — все правила выбраны (all_on).
- ◐ — хотя бы одно, но не все (enabled).
- ✗ — ни одного (not enabled).
- Значок рубрикатора не зависит от var (selected_rules[file_code]) — только от состояния правил.
- var остаётся True при «Сбросить все» (вариант B), но значок ✗.

### §6.6.36 — _populating_tree — защита от рекурсии

При _populate_rules_tree устанавливается _populating_tree = True.
_sync_plpcheck_checkbox проверяет флаг (getattr(self, '_populating_tree', False)) и выходит — иначе trace plpcheck_enabled_var → все 152 правила PlpCheck.
Флаг снимается в конце _populate_rules_tree.
